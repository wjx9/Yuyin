# 技能商店 · 使用指南（统一技能目录）

> 本文档描述 **2026-08 之后** 的技能商店模型（内置能力 + connector catalog）。
> 核心变化一句话：**加新 MCP 不再靠管理员 probe→手拼 manifest**，
> 而是往 `skill_store/connectors/*.json` 放一个 JSON（走开发/评审），
> 管理员只做**上架 / 下架**；用户启用新 MCP 时**自动弹出凭证表单**，填 Key 即用。

## 1. 角色分工

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| **开发** | 把新 MCP 写成一个 `connectors/*.json` 目录文件（评审后入库） | 不管运行期上架/下架 |
| **管理员** | 管理后台维护技能的上架状态；需要时新增技能 | 不需要了解运行时接入细节 |
| **用户** | 手机端选购 → 启用 → **填 API Key 等凭证** → 语音用起来 | 不接触 manifest/配置细节 |

数据流：`server_py/routing` 内置 Handler + `connectors/*.json` →（商店启动/主服务同步）→
`skills` 表 → 管理后台/手机端统一目录。不同接入方式只作为后端实现细节，用户看到的
都是可以被助手调用的技能。

## 2. 系统组成与启动

三个进程 + 手机 App：

| 单元 | 端口 | 路径 | 作用 |
|---|---|---|---|
| 服务端（大脑） | 8000 | `server_py/serve.py` | Gemini 意图分流 + 语音 `/chat` |
| **技能商店** | 9000 | `skill_store/main.py` | 统一技能目录 / 选购 / 启停 / 凭证 |
| mock MCP | 9100 | `server_py/mcp_skill/mock_server.py` | 演示用 MCP（天气/股票/区域） |
| 手机 App | — | `client_flutter/` | VUI 语音助手 + 技能商店页 |

### 三端运行命令（仓库根，`.venv` 已装依赖；全起 = 依次执行端1→端2→端3）

```bat
:: ── 端 1 · mock MCP（:9100，演示天气/股票/区域）────────────────────────────
::   可加 --require-auth --token xxx 模拟「全请求鉴权」的麦当劳式 MCP
.venv\Scripts\python.exe server_py\mcp_skill\mock_server.py

:: ── 端 2 · 技能商店（:9000，启动时自动把 connectors/*.json 同步进库）──────
.venv\Scripts\python -m uvicorn skill_store.main:app --host 0.0.0.0 --port 9000

:: ── 端 3 · 服务端（:8000，语音大脑；或直接双击 run_phone_server.bat 一键起 + 放行防火墙）──
.venv\Scripts\python.exe server_py\serve.py
```

> 三端各占一端口、独立进程；服务端经 `SKILL_STORE_URL` 连商店，商店目录里的 MCP 技能指向 mock（9100）。

手机 App 设置页：**服务端地址**填 `http://<电脑LAN IP>:8000`，
**商店地址**填 `http://<电脑LAN IP>:9000`（例 `http://172.24.111.152:9000`）。
手机与电脑需同一网络，且 8000/9000 防火墙入站放行。

测试与打包：

```bat
:: 商店后端单测（40 用例）
.venv\Scripts\python -m pytest skill_store\test_store.py -q

:: 手机端 widget 测试 + 静态检查 + 打 release APK
cd client_flutter
flutter test
flutter analyze
flutter build apk --release   :: 产物 build\app\outputs\flutter-apk\app-release.apk
```

## 3. 手机端商城怎么用（用户视角）

打开 App → 技能商店，看到每张技能卡：图标、名称、描述、关键词、凭证状态、启用开关。

**三态语义**：

| 状态 | 含义 | 怎么到 |
|---|---|---|
| 未选购 | 还没拥有 | — |
| 已选购 · 未启用 | 买了但没开，不路由 | 开启后停用（保留选购） |
| 已启用 | 语音助手会路由到它 | 打开开关 |

### 3.1 启用一个新 MCP（重点）

1. 打开目标技能的**启用开关**。
2. 若是需凭证的 MCP（byok，如麦当劳/东财），**立即自动弹出凭证表单**。
3. 按提示填字段（API Key / Token / 下拉选项等），点保存。
4. 语音助手 **≤30s** 生效——直接说触发话术即可（如「贵州茅台今天最新价」「帮我点麦当劳」）。

> 凭证状态行：黄色「需配置凭证」→ 配置后变绿色「凭证已配置」。
> 已配置的 secret 再打开表单不会回填明文，留空 = 保留旧值。

### 3.2 停用 / 退订

- **停用**（关开关）：保留选购，技能不再路由，随时可再开。
- **退订**：移除选购（连带停用），卡片消失。
- 管理员下架的技能：你已选购的仍显示在「已下架」区，可停用/退订清理，不会被静默夺走。

## 4. 管理后台怎么用（管理员视角）

地址：`http://<电脑LAN IP>:9000/`（即商店根路径，浏览器打开）。

### 4.1 技能目录（主区）

- 列出 `publisher='catalog'` 的全部技能，含**已下架**的（⚪）。
- 每行只有两个操作：**上架 / 下架**。
  - 上架（🟢）→ 用户端目录可见、可选购启用。
  - 下架（⚪）→ 用户端目录隐藏，但已选购用户的卡保留（可停用/退订）。
- 顶部**「重新同步目录」**按钮：改了 `connectors/*.json` 后免重启商店，立即同步生效。

### 4.2 技能维护（次区）

- `publisher != 'catalog'` 的技能（历史手动发布的、或走逃生通道加的）。
- 操作：上架/下架 + **删除**（删除会从所有用户选购里移除）。
- 一般不需要——**新 MCP 走目录（见 §5）**。

### 4.3 高级：添加远程技能

折叠在「高级：添加自定义 MCP」里，仅当目录模式不够用才用：
1. 填 MCP server 地址 →「发现工具」。
2. 需鉴权的填临时 Token，或展开「自定义请求头 JSON」填 `X-API-Key` 等非 Bearer 头。
3. 自动带出 manifest 表单，改 intent/关键词/credentials JSON → 发布。

> probe 的临时 Token **不保存**，只用于本次发现请求。

## 5. 添加新 MCP 的具体操作（核心）

### 5.1 官方 MCP（推荐，10 分钟）

**三步：写 JSON → 同步 → 上架。**

#### 第 1 步：写 `skill_store/connectors/<你的>.json`

模板（字段全解见下）：

```json
{
  "skill_id": "xxx-mcp",
  "name": "技能显示名",
  "icon": "📊",
  "description": "给语音助手看的描述：什么场景用、能答什么",
  "intent": "xxx_mcp",
  "pc_only": false,
  "entry_tool": "入口工具名",
  "query_slot": "query",
  "keywords": ["关键词1", "关键词2"],
  "replaces": [],
  "mcp_server": { "transport": "http", "url": "https://你的-mcp-地址" },
  "credentials": {
    "type": "none",
    "schema": []
  },
  "tools": [
    {
      "name": "入口工具名",
      "description": "工具说明（LLM 用）",
      "input_schema": { "type": "object", "properties": { "query": { "type": "string" } }, "required": ["query"] }
    }
  ],
  "default_status": "inactive"
}
```

**字段全解**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `skill_id` | ✅ | 唯一 ID，如 `eastmoney-mcp` |
| `name` | ✅ | 展示名 |
| `icon` | | emoji 图标 |
| `description` | | 语音助手判断「何时用本技能」的依据 |
| `intent` | ✅ | 唯一意图 ID，如 `eastmoney_mcp`；**不能撞内置 intent**（见 §8） |
| `entry_tool` | ✅ | 该 MCP 的入口工具名（服务器首次调用它） |
| `query_slot` | | 缺槽位时把整句 query 喂给哪个参数（如 `query`） |
| `keywords` | | 命中即**确定性路由**到本技能 |
| `replaces` | | 买了本技能后顶替的内置 intent 列表 |
| `mcp_server.url` | ✅ | MCP 地址；`transport` 是装饰字段，实际只读 url |
| `credentials` | ✅ | 凭证声明：`none`（无需）或 `byok`（用户填） |
| `tools` | ✅ | 至少放 entry_tool 的 schema（probe 过一次就能抓全） |
| `default_status` | | `active`（同步即上架）/ `inactive`（待上架，缺省） |

#### credentials.schema 字段全解（byok）

```json
"credentials": {
  "type": "byok",
  "schema": [
    {
      "key": "em_api_key",
      "label": "东方财富 API Key",
      "type": "secret",
      "required": true,
      "help": "获取方式说明（表单里显示）",
      "placeholder": "输入 Key",
      "inject": { "where": "header", "name": "em_api_key" }
    },
    {
      "key": "region",
      "label": "区域",
      "type": "select",
      "required": true,
      "options": ["cn", "us"],
      "inject": { "where": "query", "name": "region" }
    }
  ]
}
```

- `type`：`secret`（密码框）/ `string` / `number` / `select`（下拉）/ `boolean`（是/否）/ `textarea`、`file`（手机端按 secret 处理）。
- `required`：必填；已配置后 secret 留空 = 保留旧值。
- `inject`：凭证注入方式
  - `{"where":"header","name":"Authorization","prefix":"Bearer "}` → 请求头加 `Authorization: Bearer <值>`
  - `{"where":"header","name":"em_api_key"}` → 非 Bearer，直接用 `em_api_key: <值>`
  - `{"where":"query","name":"region"}` → 拼进 URL query
- 一个技能可声明多个字段（如 region 的 `api_key` + `region`），表单自动按 schema 渲染。

> **无鉴权 MCP** 用 `"credentials": {"type": "none"}`（见 `weather.json` / `stock.json`）。

#### 第 2 步：同步进库

改完 `connectors/*.json` 后二选一：
- **管理后台点「重新同步目录」**（推荐，免重启）；或
- 重启商店（启动时自动同步）。

同步语义（幂等，放心反复点）：
- **新行**取 `default_status`（缺省 `inactive` = 待上架，不会悄悄上线）。
- **已有行**的 status 不被触碰——管理员之前的上架/下架保留。
- 只有 manifest 真正变化才给已选购用户 bump 版本（server ≤30s 重建路由图）。

#### 第 3 步：上架

管理后台「官方 MCP 目录」里找到它 → 点**上架**。用户端立即可见、可启用。

**复用现成范例**：`weather.json`（无凭证）、`region.json`（多字段 byok + select）、
`mcdonalds.json`（Bearer 注入）、`eastmoney.json`（非 Bearer 头注入）。拷一个改最省事。

### 5.2 自定义 MCP（逃生通道）

不走目录，直接用管理后台「高级：添加自定义 MCP」probe → 手拼 manifest（§4.3）。
适合：临时调试、目录外的私有 MCP。发布后它出现在「自定义 MCP」区，同样可上架/下架/删除。

### 5.3 内置能力与意图冲突

`POST /skills` 会校验：intent 撞内置能力（天气/闹钟/地图/新闻/音乐等，见
`skill_store/main.py` 的 `_BUILTIN_INTENTS`）→ **409**，上架直接拦下。
想顶替内置能力用 `replaces` 字段，而不是复用同名 intent。

## 6. 接口速查

| 方法 & 路径 | 谁用 | 说明 |
|---|---|---|
| `GET /` | 管理员 | 管理后台静态页 |
| `GET /skills` | 手机端 | 目录（仅 active 技能 + 完整 manifest） |
| `POST /skills` | 管理员 | 上架/更新（manifest + 可选 status/publisher）；撞内置 intent → 409 |
| `POST /skills/probe` | 管理员 | probe 发现工具（`{mcp_server, probe_headers?}`） |
| `POST /skills/sync-all` | 管理员 | 同步全部技能目录，返回 `{synced, bumped}` |
| `POST /skills/catalog/sync` | 管理员 | 兼容旧客户端，仅同步远程 connector 目录 |
| `PUT /skills/{skill_id}/status` | 管理员 | 任意技能统一上架/下架 |
| `GET /skills/admin` | 管理员 | 全部技能（含已下架）；来源字段仅供后端管理 |
| `GET /skills/{skill_id}` | 管理员 | 单技能 manifest |
| `DELETE /skills/{skill_id}` | 管理员 | 硬删（级联清理选购，bump 持有者） |
| `GET /me/skills?user_id=` | 手机端 | 已选购 + 启停状态 |
| `GET /me/skills/detail?user_id=` | 手机端 | 已选购详情（含已下架） |
| `PUT /me/skills/enabled` | 手机端 | 单技能启/停（开启自动选购），写后 version+1 |
| `PUT /me/skills/remove` | 手机端 | 退订（级联删凭证） |
| `GET /me/credentials?user_id=&skill_id=` | 手机端 | 凭证状态（**脱敏**） |
| `GET /me/credentials/plain?user_id=&skill_id=` | server_py | 凭证明文（仅服务端内部） |
| `PUT /me/credentials` | 手机端 | 保存凭证（AES-GCM 加密），写后 version+1 |
| `DELETE /me/credentials` | 手机端 | 删除凭证 |
| `GET /me/skills/sync?user_id=` | server_py | 拉取该用户 `{version, skills}`，据此重建路由图 |

## 8. 常见问题

**Q：probe 一直超时？**
probe 超时上限 30s；麦当劳 `list_tools` 约 18s、东财约 6s 都在范围内。
确认商店已重启加载新代码（旧进程是 10s 上限）。确认地址是 MCP 端点
（`https://ai.eastmoney.com/mxmcp` 是聊天网页不是 MCP，真实端点是
`https://mxapi.eastmoney.com/mxds/mcp`）。

**Q：非 Bearer 鉴权的 MCP（如东财 `em_api_key`）怎么探？**
管理后台「高级：自定义请求头 JSON」填 `{"em_api_key":"你的Key"}`，probe 会把
它叠加到临时 Token 之上。目录技能不需要——凭证在 `credentials.schema` 里声明即可。

**Q：同步会不会把管理员下的架又翻上来？**
不会。`ON CONFLICT DO UPDATE` 不碰 `status`，已有行的上架/下架状态保留；
`default_status` 只对**新行**生效。

**Q：改 `connectors/*.json` 后用户路由没变？**
确认已同步（管理后台点「重新同步目录」），且 manifest 确实变了——只有变化才会
bump 版本，server 侧 ≤30s 重建路由。

## 9. 安全要点

- 凭证用 `STORE_MASTER_KEY`（env 提供，勿硬编码）AES-GCM 加密落库，写凭证缺主密钥 **fail-closed** 500。
- 手机端拿到的永远是**脱敏**凭证状态；明文只经 `/me/credentials/plain` 给服务端内部使用。
- 管理后台 probe 的临时 Token 不保存；仅用于本次发现请求。
- `mock-secret-key-123` 是 mock 演示值，仅本地 mock server 接受。
