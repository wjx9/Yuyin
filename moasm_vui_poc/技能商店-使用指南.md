## 1. 角色分工

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| **开发** | 把新 MCP 写成一个 `connectors/*.json` 目录文件（评审后入库） | 不管运行期上架/下架 |
| **管理员** | 管理后台维护技能的上架状态；需要时新增技能 | 不需要了解运行时接入细节 |
| **用户** | 手机端选购 → 启用 → **填 API Key 等凭证** → 语音用起来 | 不接触 manifest/配置细节 |

数据流：`server_py/routing` 内置 Handler + `connectors/*.json` →（商店启动/主服务同步）→
`skills` 表 → 管理后台/手机端统一目录。不同接入方式只作为后端实现细节，用户看到的
都是可以被助手调用的技能。

## 2. 系统组成与启动

三个进程 + 手机 App：

| 单元 | 端口 | 路径 | 作用 |
|---|---|---|---|
| 服务端（大脑） | 8000 | `server_py/serve.py` | Gemini 意图分流 + 语音 `/chat` |
| **技能商店** | 9000 | `skill_store/main.py` | 统一技能目录 / 选购 / 启停 / 凭证 |
| mock MCP | 9100 | `server_py/mcp_skill/mock_server.py` | 演示用 MCP（天气/股票/区域） |
| 手机 App | — | `client_flutter/` | VUI 语音助手 + 技能商店页 |

### 三端运行命令（仓库根，`.venv` 已装依赖；全起 = 依次执行端1→端2→端3）

```bat
:: ── 端 1 · mock MCP（:9100，演示天气/股票/区域）────────────────────────────
::   可加 --require-auth --token xxx 模拟「全请求鉴权」的麦当劳式 MCP
.venv\Scripts\python.exe server_py\mcp_skill\mock_server.py

:: ── 端 2 · 技能商店（:9000，启动时自动把 connectors/*.json 同步进库）──────
.venv\Scripts\python -m uvicorn skill_store.main:app --host 0.0.0.0 --port 9000

:: ── 端 3 · 服务端（:8000，语音大脑；或直接双击 run_phone_server.bat 一键起 + 放行防火墙）──
.venv\Scripts\python.exe server_py\serve.py
```

> 三端各占一端口、独立进程；服务端经 `SKILL_STORE_URL` 连商店，商店目录里的 MCP 技能指向 mock（9100）。

手机 App 设置页：**服务端地址**填 `http://<电脑LAN IP>:8000`，
**商店地址**填 `http://<电脑LAN IP>:9000`（例 `http://172.24.111.152:9000`）。
手机与电脑需同一网络，且 8000/9000 防火墙入站放行。

测试与打包：

```bat
:: 商店后端单测（42 用例）
.venv\Scripts\python -m pytest skill_store\test_store.py -q

:: 手机端 widget 测试 + 静态检查 + 打 release APK
cd client_flutter
flutter test
flutter analyze
flutter build apk --release   :: 产物 build\app\outputs\flutter-apk\app-release.apk
```

## 3. 手机端商城怎么用（用户视角）

打开 App → 技能商店，看到每张技能卡：图标、名称、描述、关键词、凭证状态、启用开关。

**三态语义**：

| 状态 | 含义 | 怎么到 |
|---|---|---|
| 未选购 | 还没拥有 | — |
| 已选购 · 未启用 | 买了但没开，不路由 | 开启后停用（保留选购） |
| 已启用 | 语音助手会路由到它 | 打开开关 |

### 3.1 启用一个新 MCP（重点）

1. 打开目标技能的**启用开关**。
2. 若是需凭证的 MCP（byok，如麦当劳/东财），**立即自动弹出凭证表单**。
3. 按提示填字段（API Key / Token / 下拉选项等），点保存。
4. 语音助手 **≤30s** 生效——直接说触发话术即可（如「贵州茅台今天最新价」「帮我点麦当劳」）。

> 凭证状态行：黄色「需配置凭证」→ 配置后变绿色「凭证已配置」。
> 已配置的 secret 再打开表单不会回填明文，留空 = 保留旧值。

**凭证自动复用（2026-08 新增）**：

若你已经为同一个 MCP server 的另一个技能配置过凭证（例如已配置「麦当劳门店查询」的 Token），启用同 server 的其他技能（如「麦当劳一键领券」「麦当劳积分抽奖」「麦当劳我的优惠券」「麦当劳麦麦商城」）时，系统会**自动复用凭证**，无需重复填写。

复用条件：
- 目标技能是 `byok` 类型（需要凭证）
- 目标技能尚未配置凭证
- 存在另一个已配置凭证的技能，其 `mcp_server.url` 和凭证字段定义（key/type/required/inject）相同

复用成功时，启用接口返回 `credentials_reused: true` 和 `reused_from: <来源技能ID>`。凭证仍然独立存储，后续修改某个技能的凭证不会影响其他技能。

### 3.2 停用 / 退订

- **停用**（关开关）：保留选购，技能不再路由，随时可再开。
- **退订**：移除选购（连带停用），卡片消失。
- 管理员下架的技能：你已选购的仍显示在「已下架」区，可停用/退订清理，不会被静默夺走。

## 4. 管理后台怎么用（管理员视角）

地址：`http://<电脑LAN IP>:9000/`（即商店根路径，浏览器打开）。

### 4.1 技能目录（统一目录表）

- 列出**全部技能**（含 `publisher='catalog'` 官方目录、`publisher='builtin'` 内置能力、自定义 MCP），含**已下架**的（⚪）。
- 每行操作：**上架 / 下架**；
  - 上架（🟢）→ 用户端目录可见、可选购启用。
  - 下架（⚪）→ 用户端目录隐藏，但已选购用户的卡保留（可停用/退订）。
- **删除按钮**：仅自定义 MCP（publisher 非 catalog/builtin）显示，硬删会从所有用户选购里移除；官方目录和内置能力由代码/目录管理，不显示删除按钮。
- 顶部**「重新同步目录」**按钮：改了 `connectors/*.json` 后免重启商店，调用 `POST /skills/sync-all` 立即同步 connector + 内置能力。

### 4.2 高级：添加远程技能

折叠在「高级：添加自定义 MCP」里，仅当目录模式不够用才用（详细步骤见 §5.2）：
1. 填 MCP server 地址 →「发现工具」。
2. 需鉴权的填临时 Token，或展开「自定义请求头 JSON」填 `X-API-Key` / `em_api_key` 等非 Bearer 头。
3. 自动带出 manifest 表单，改 intent/关键词/credentials JSON → 发布。
4. 发布后出现在统一目录表中（publisher 非 catalog/builtin，有删除按钮）。

> probe 的临时 Token **不保存**，只用于本次发现请求。

## 5. 添加新 MCP 的具体操作（核心）

> **方式选择**：
> - ✅ **推荐：官方目录（§5.1）** —— 开发写 `connectors/*.json` 走评审，管理员只上架/下架，可追溯、可版本管理，适合所有正式接入的 MCP。
> - ⚠️ **仅逃生：自定义 MCP（§5.2）** —— 管理后台 probe → 手拼 manifest，不走评审，仅用于临时调试、目录外的私有 MCP。

---

### 5.1 官方 MCP（推荐，10 分钟）

**五步：写 JSON → 获取 tools schema → 同步 → 上架 → 启用验证。**

#### 第 1 步：写 `skill_store/connectors/<你的>.json`

模板（字段全解见下）：

```json
{
  "skill_id": "xxx-mcp",
  "name": "技能显示名",
  "icon": "📊",
  "description": "给语音助手看的描述：什么场景用、能答什么",
  "intent": "xxx_mcp",
  "pc_only": false,
  "entry_tool": "入口工具名",
  "query_slot": "query",
  "keywords": ["关键词1", "关键词2"],
  "replaces": [],
  "mcp_server": { "transport": "http", "url": "https://你的-mcp-地址/mcp" },
  "credentials": {
    "type": "none",
    "schema": []
  },
  "tools": [
    {
      "name": "入口工具名",
      "description": "工具说明（LLM 用）",
      "input_schema": { "type": "object", "properties": { "query": { "type": "string" } }, "required": ["query"] }
    }
  ],
  "default_status": "inactive"
}
```

**字段全解**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `skill_id` | ✅ | 唯一 ID，如 `eastmoney-mcp`；不能与已有技能重复 |
| `name` | ✅ | 展示名 |
| `icon` | | emoji 图标 |
| `description` | | 语音助手判断「何时用本技能」的依据 |
| `intent` | ✅ | 唯一意图 ID，小写下划线，如 `eastmoney_mcp`；**不能撞 22 个内置 intent**（见 §5.3），撞了上架 409 |
| `entry_tool` | ✅ | 该 MCP 的入口工具名（服务器首次调用它），必须与 MCP server 实际工具名一致 |
| `query_slot` | | 缺槽位时把整句 query 喂给哪个参数（如 `query`、`text`、`city`） |
| `keywords` | | 命中即**确定性路由**到本技能，建议 3~10 个覆盖用户典型说法 |
| `replaces` | | 买了本技能后顶替的内置 intent 列表（如 `["amap_weather_live"]`） |
| `mcp_server.url` | ✅ | MCP 真实端点（注意：很多 MCP 官网首页不是端点，真实端点常带 `/mcp` 后缀）；`transport` 是装饰字段，实际只读 url |
| `credentials` | ✅ | 凭证声明：`none`（无需）或 `byok`（用户填，见下） |
| `tools` | ✅ | 至少放 entry_tool 的完整 `input_schema`（获取方式见第 2 步） |
| `default_status` | | `active`（同步即上架）/ `inactive`（待上架，缺省）；新技能建议 `inactive` |
| `pc_only` | | 可声明仅 PC 可见（如 `music_control`） |

##### credentials.schema 字段全解（byok）

需用户填凭证的 MCP，把 `credentials` 改为：

```json
"credentials": {
  "type": "byok",
  "schema": [
    {
      "key": "api_key",
      "label": "API Key",
      "type": "secret",
      "required": true,
      "help": "在 XX 开放平台控制台获取 API Key",
      "placeholder": "输入 Key",
      "inject": { "where": "header", "name": "Authorization", "prefix": "Bearer " }
    },
    {
      "key": "region",
      "label": "区域",
      "type": "select",
      "required": true,
      "options": ["cn", "us"],
      "inject": { "where": "query", "name": "region" }
    }
  ]
}
```

- `type`：`secret`（密码框）/ `string` / `number` / `select`（下拉，需配 `options`）/ `boolean`（是/否）/ `textarea`、`file`（手机端按 secret 处理）。
- `required`：必填；已配置后 secret 留空 = 保留旧值（脱敏 GET 不回传明文，用户只改非敏感字段时不会清掉已存密钥）。
- `inject`：凭证注入方式，三种写法：
  - Bearer 鉴权（最常见）：`{"where":"header","name":"Authorization","prefix":"Bearer "}` → 请求头加 `Authorization: Bearer <值>`
  - 非 Bearer 头（如东财）：`{"where":"header","name":"em_api_key"}` → 直接用 `em_api_key: <值>`
  - Query 参数：`{"where":"query","name":"region"}` → 拼进 URL query
- 一个技能可声明多个字段（如 region 的 `api_key` + `region`），手机端表单自动按 schema 动态渲染，无需为新 MCP 改客户端代码。

> **无鉴权 MCP** 用 `"credentials": {"type": "none"}`（见 `weather.json` / `stock.json`）。

#### 第 2 步：获取 entry_tool 的 input_schema

`tools` 数组至少要包含 `entry_tool` 的完整 `input_schema`（含 `properties` 和 `required`）。获取方式二选一：

**方式 A：管理后台 probe 发现（推荐）**
1. 打开管理后台 `http://<PC IP>:9000/`
2. 展开「高级：添加自定义 MCP」
3. 填 MCP server 地址 → 点「发现工具」
4. 需鉴权的填临时 Token（Bearer）或展开「自定义请求头 JSON」填非 Bearer 头（如 `{"em_api_key":"xxx"}`）
5. 发现成功后，从结果中复制工具的 `name`、`description`、`input_schema` 填入 connector JSON
6. probe 的临时 Token **不保存**，仅本次发现用

**方式 B：手动调用 MCP list_tools（脚本）**

```python
import asyncio
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client

async def main():
    url = "https://你的-mcp-地址/mcp"
    headers = {"Authorization": "Bearer 你的临时Token"}  # 无需鉴权则传 None
    async with streamable_http_client(url, headers=headers) as (r, w, *_):
        async with ClientSession(r, w) as session:
            await session.initialize()
            res = await session.list_tools()
            for t in res.tools:
                print(f"=== {t.name} ===")
                print(t.description)
                print(dict(t.input_schema))

asyncio.run(main())
```

#### 第 3 步：同步进库

改完 `connectors/*.json` 后二选一：
- **管理后台点「重新同步目录」**（推荐，免重启）→ 调用 `POST /skills/sync-all`，同时同步 connector 目录与内置能力；或
- 重启商店（启动时 `lifespan` 自动同步 connector + builtin）。

同步语义（幂等，放心反复点）：
- **新行**取 `default_status`（缺省 `inactive` = 待上架，不会悄悄上线）。
- **已有行**的 status 不被触碰——管理员之前的上架/下架保留。
- 只有 manifest 真正变化才给已选购用户 bump 版本（server ≤30s 重建路由图）；无变化不写库、不 bump。

**验证同步成功：**

```bash
# 管理员视角：检查新技能是否在库中（含已下架）
curl http://127.0.0.1:9000/skills/admin | python -m json.tool
```

确认返回的列表中包含新技能的 `skill_id`，`publisher` 为 `catalog`，`status` 为 `inactive`（或你设的 `default_status`）。

#### 第 4 步：上架

1. 打开管理后台 `http://<PC IP>:9000/`
2. 在统一技能目录表中找到新技能（状态为 ⚪ 已下架）
3. 点「上架」按钮 → 状态变为 🟢 已上架

**验证上架成功：**

```bash
# 用户端目录：仅 active 技能，应包含新技能
curl http://127.0.0.1:9000/skills | python -m json.tool
```

确认返回的 `skills` 列表中包含新技能的完整 manifest。

#### 第 5 步：手机端启用 + 配凭证 + 语音验证

1. 打开手机 App → 技能商店
2. 找到新技能卡片，打开**启用开关**
3. 若是 byok 技能，**立即自动弹出凭证表单** → 按提示填 API Key 等字段 → 保存
   - 凭证状态行：黄色「需配置凭证」→ 配置后变绿色「凭证已配置」
   - 已配置的 secret 再打开表单不会回填明文，留空 = 保留旧值
4. 等待 **≤30s** 热插拔生效（商店 version+1 → 服务端 SkillRegistry TTL 到期重建路由图）
5. 说触发话术验证（如「把你好翻译成英文」），确认意图路由到新技能且返回正确数据

**命令行验证（无需手机，确认服务端路由生效）：**

```bash
curl -X POST http://127.0.0.1:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"query":"你的触发话术","user_id":"test-user-001","session_id":"s1","platform":"mobile"}' \
  | python -m json.tool
```

检查返回的 `intent` 字段是否为新技能的 intent（如 `translate_mcp`），`text` 是否包含 MCP 返回的正确数据。

**复用现成范例**（拷一个改最省事）：

| 范例文件 | 凭证形态 | 适用场景 |

> **麦当劳 MCP 系列**：5 个技能共用同一个 MCP server（`https://mcp.mcd.cn`）和同一个 Token，启用时凭证自动复用（见 §3.1）。这是「一个 MCP server 拆成多个独立技能」的典型范例——每个技能有独立的 intent、entry_tool、keywords，但凭证 schema 相同。

**快速检查清单（发布前必过）：**

- [ ] `skill_id` 全局唯一
- [ ] `intent` 全局唯一，**不撞 22 个内置 intent**
- [ ] `entry_tool` 与 MCP server 实际工具名一致
- [ ] `mcp_server.url` 是真实 MCP 端点（不是官网首页）
- [ ] `tools` 数组包含 entry_tool 的完整 `input_schema`
- [ ] byok 技能的 `credentials.schema` 每个字段都有 `inject`
- [ ] `keywords` 覆盖用户典型说法（3~10 个）
- [ ] `default_status` 新技能建议 `inactive`（待上架）
- [ ] 同步后管理后台能看到新技能（`GET /skills/admin`）
- [ ] 上架后用户端目录能看到新技能（`GET /skills`）
- [ ] 手机端启用后 ≤30s 语音调用成功（`intent` 正确）

### 5.2 自定义 MCP（逃生通道，5 分钟）

不走目录，直接用管理后台 probe → 手拼 manifest。适合：临时调试、目录外的私有 MCP、快速验证。

**四步：probe 发现工具 → 填写 manifest → 发布 → 验证。**

#### 第 1 步：打开管理后台高级区

打开 `http://<PC IP>:9000/` → 展开「**高级：添加自定义 MCP**」折叠区。

#### 第 2 步：probe 发现工具

1. **MCP server 地址**：填真实端点（如 `https://mcp.example.com/mcp`）
2. **临时 Token**（可选）：需 Bearer 鉴权的 MCP 填，仅本次发现用，**不保存、不入库**
3. **自定义请求头 JSON**（可选）：非 Bearer 鉴权（如东财 `em_api_key`）填，如：
   ```json
   {"em_api_key": "你的Key"}
   ```
   会叠加到上面的 Bearer Token 之上，键冲突以高级框为准
4. 点「**发现工具**」→ 成功后显示工具列表，发布表单自动展开

**probe 常见错误与处理：**

| 错误提示 | 原因 | 处理 |
|---|---|---|
| 鉴权失败（HTTP 401/403） | 临时 Token 缺失或无效 | 填正确的 Token 或请求头 |
| 该地址返回的是网页（HTTP 2xx，text/html） | 填了管理网页而非 MCP 端点 | 找真实 MCP endpoint（常带 `/mcp` 后缀） |
| 地址不存在（HTTP 404） | URL 路径错误 | 检查 URL 路径 |
| 该地址不是 MCP endpoint（HTTP 405） | 地址不接受 MCP 握手请求 | 确认地址支持 streamable-http |
| 请求过频（HTTP 429） | 限流 | 稍后重试 |
| 连接超时（>30s） | MCP server 不可达或太慢 | 确认网络、确认地址可达；真实麦当劳 MCP list_tools 约 18s 属正常 |

#### 第 3 步：填写并发布 manifest

probe 成功后表单已自动带出工具列表和默认值，需要填写/确认：

| 字段 | 说明 |
|---|---|
| 技能 ID | 自动填 `<工具名>-mcp`，可改，需全局唯一 |
| 入口工具 | 下拉选择，默认第一个；切换时自动带出名称/描述 |
| 名称 / 图标 / 描述 | 自动带出，可改 |
| **intent** | **必须唯一，不能撞内置**（输入时实时提示 ⚠️ 撞内置能力） |
| 关键词 | 逗号分隔，命中即确定性路由 |
| 顶替内置 intent | 逗号分隔，可选（买了本技能后内置让位） |
| query_slot | 可选，缺槽位时整句 query 喂给哪个参数 |
| credentials JSON | 默认 `{"type":"none"}`；byok 改成 schema 声明（格式见 §5.1） |

点「**新增（发布）**」按钮：
- 成功：返回 `✅ 已发布 <skill_id>（status=active）`
- 失败（撞内置 intent）：返回 409，修改 intent 后重试
- 失败（撞其他 active 技能同 intent）：返回 409，修改 intent 后重试

#### 第 4 步：验证 + 使用

发布后技能出现在统一技能目录表中（`publisher` 非 catalog/builtin，**有删除按钮**），status=active。后续启用、配凭证、语音验证同 §5.1 第 5 步。

自定义 MCP 与官方目录技能的区别：

| 维度 | 官方目录（§5.1） | 自定义 MCP（§5.2） |
|---|---|---|
| 存储 | `connectors/*.json` 文件（可版本管理、可评审） | 仅数据库（无文件追溯） |
| publisher | `catalog` | `poc` 等（非 catalog/builtin） |
| 管理后台操作 | 上架/下架（**不可删除**） | 上架/下架/**删除** |
| 适用场景 | 正式接入 | 临时调试、私有 MCP |

### 5.3 内置能力与意图冲突

`POST /skills` 会校验：intent 撞内置能力（闲聊/闹钟/高德全家桶/新闻/出行/快递/音乐等共 **22 个**，见
`skill_store/main.py` 的 `_BUILTIN_INTENTS`）→ **409**，上架直接拦下。
服务端装配时再过滤一次（双保险），撞内置 intent 的 MCP 技能会被静默跳过。

想顶替内置能力用 `replaces` 字段（如 `"replaces": ["amap_weather_live"]`），用户启用后该内置 intent 从 dispatcher 和计划器白名单中剔除，而不是复用同名 intent。

## 8. 常见问题

**Q：probe 一直超时？**
probe 超时上限 30s；麦当劳 `list_tools` 约 18s、东财约 6s 都在范围内。
确认商店已重启加载新代码（旧进程是 10s 上限）。确认地址是 MCP 端点
（`https://ai.eastmoney.com/mxmcp` 是聊天网页不是 MCP，真实端点是
`https://mxapi.eastmoney.com/mxds/mcp`）。

**Q：非 Bearer 鉴权的 MCP（如东财 `em_api_key`）怎么探？**
管理后台「高级：自定义请求头 JSON」填 `{"em_api_key":"你的Key"}`，probe 会把
它叠加到临时 Token 之上。目录技能不需要——凭证在 `credentials.schema` 里声明即可。

**Q：同步会不会把管理员下的架又翻上来？**
不会。`ON CONFLICT DO UPDATE` 不碰 `status`，已有行的上架/下架状态保留；
`default_status` 只对**新行**生效。

**Q：改 `connectors/*.json` 后用户路由没变？**
确认已同步（管理后台点「重新同步目录」），且 manifest 确实变了——只有变化才会
bump 版本，server 侧 ≤30s 重建路由。

**Q：启用第二个麦当劳技能时还需要填 Token 吗？**
不需要。系统会自动复用同一个 MCP server 的凭证（见 §3.1「凭证自动复用」）。
只要你已经为「麦当劳门店查询」配置过 Token，启用「一键领券」「积分抽奖」「我的优惠券」「麦麦商城」时都会自动复用，无需重复填写。

**Q：凭证自动复用后，修改一个技能的 Token 会影响其他技能吗？**
不会。复用只是「启用时自动复制一份」，每个技能的凭证仍然独立存储。
后续你修改某个技能的凭证，不会影响其他同 server 的技能。

**Q：什么情况下凭证不会自动复用？**
- 目标技能已经配置过凭证（以已配置的为准）
- 没有其他已配置凭证的同 MCP server 技能
- 两个技能的凭证字段定义不同（如一个是 Bearer Token，另一个是 API Key + region）
- 目标技能不是 byok 类型（如 none 类型无需凭证）

## 9. 安全要点

- 凭证用 `STORE_MASTER_KEY`（env 提供，勿硬编码）AES-GCM 加密落库，写凭证缺主密钥 **fail-closed** 500。
- 手机端拿到的永远是**脱敏**凭证状态；明文只经 `/me/credentials/plain` 给服务端内部使用。
- 管理后台 probe 的临时 Token 不保存；仅用于本次发现请求。
- `mock-secret-key-123` 是 mock 演示值，仅本地 mock server 接受。
