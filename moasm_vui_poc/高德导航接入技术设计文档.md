## 1. 背景与目标

### 1.1 背景

雷鸟语音助手需要接入高德导航能力，支持用户通过语音发起导航、选择地址、控制导航等操作。经过预研讨论，确定采用**引入高德 Agent SDK**的技术方案：端侧集成高德导航 Agent，Agent 内部封装高德导航 SDK 的原子能力，提供导航域的完整对话流程。

### 1.2 核心挑战

引入 Agent SDK 带来一个核心问题：**对话控制权的交接**。



* 用户与系统级语音助手（"小雷"）对话时，预期是全局助手在回答；

* 一旦意图命中导航，对话控制权交给高德 Agent，Agent 接管后续对话；

* Agent 在非导航场景的能力弱于主语音助手，用户可能问闹钟、天气等 Agent 不支持的问题；

* 如果无提示地 "陷入"Agent，用户体验会很奇怪。

因此，本方案的核心设计目标是：**在利用高德 Agent 导航域能力的同时，解决对话控制权交接和非导航意图处理的体验问题**。

### 1.3 目标



* 定义端侧高德 Agent 的集成方式和能力边界；

* 设计主语音助手与高德 Agent 之间的对话控制权交接机制；

* 定义端云通信协议，支持云侧调用端侧 Agent 能力；

* 设计状态机，支持用户在导航流程中 "不按套路出牌" 的边界场景；

* 明确意图路由机制，确保非导航请求能回退到主语音助手处理；

* 覆盖 5 个关键边界场景，保证用户体验一致、可预期。

### 1.4 非目标



* 不定义高德 Agent SDK 内部的实现细节；

* 不涉及眼镜端（0x20）的导航 UI 适配；

* 不覆盖导航过程中的实时路线规划、偏航重算等高德内部能力；

* 不定义端云长连接的底层传输协议（假设现有长连接已支持云→端下行消息）。

## 2. 技术选型

### 2.1 选型结论

**引入高德导航 Agent SDK，端侧集成高德 Agent，Agent 内部封装高德导航 SDK。**

### 2.2 选型对比



| 维度             | 纯 SDK + 工具封装            | 引入 Agent SDK（本方案）            |
| -------------- | ----------------------- | ---------------------------- |
| 本质             | 端侧封装 SDK 原子接口，云侧自己做对话编排 | 端侧集成 Agent，Agent 提供导航域完整对话能力 |
| 导航域对话管理        | 云侧自己实现                  | Agent 内置，成熟稳定                |
| POI 搜索与选择交互    | 云侧自己实现                  | Agent 内置                     |
| 端侧开发量          | 较大                      | 较小                           |
| 云侧开发量          | 较大（需实现完整导航对话状态机）        | 较小（导航域对话交给 Agent）            |
| 对话体验可控性        | 完全可控                    | Agent 内部黑盒，部分不可控             |
| 非导航意图处理        | 主助手直接处理，体验好             | 需要设计回退机制                     |
| "陷入子 Agent" 风险 | 不存在                     | 存在，需设计显式交接机制                 |
| 导航启动延迟         | 最低（直接调 SDK）             | 多一层 Agent 转发                 |
| 上线速度           | 较慢                      | 较快                           |

### 2.3 选择引入 Agent SDK 的理由



1. **导航域能力成熟**：高德 Agent 在导航域的意图识别、POI 搜索、地址选择、导航控制等方面经过大量用户验证，能力成熟；

2. **开发效率高**：Agent 已内置完整导航对话流程，端侧和云侧不需要从零实现导航域状态机和交互逻辑；

3. **快速验证**：可以快速跑通导航全流程，验证高德导航能力在雷鸟场景下的可行性；

4. **POI 搜索质量有保障**：高德 Agent 内部的 POI 搜索、排序、消歧逻辑经过优化，比自己封装 SDK 效果更好。

### 2.4 引入 Agent SDK 的风险与应对



| 风险              | 影响                         | 应对措施                                     |
| --------------- | -------------------------- | ---------------------------------------- |
| 非导航意图处理差        | 用户在 Agent 接管期间问闹钟 / 天气，体验差 | 设计**控制权回退机制**，Agent 识别到非导航意图时主动交还控制权给主助手 |
| "陷入子 Agent" 无提示 | 用户不知道现在是谁在回答，预期混乱          | 设计**显式进入 / 退出机制**，进入和退出 Agent 时都有语音提示    |
| Agent 话术与品牌不一致  | Agent 的回复风格可能与 "小雷" 不一致    | 尽量通过 Agent 配置项调整话术；关键节点由主助手生成回复          |
| 边界场景不可控         | Agent 对极端输入的处理不可预测         | 关键边界场景（无目的地、搜不到、直接导航）在主助手层前置处理           |
| 导航中控制延迟         | 结束 / 重新导航多一层 Agent 转发      | 导航控制指令由主助手直接调 Agent 控制接口，不经过对话交互         |

### 3.2 职责划分



| 角色             | 职责                                       | 不负责                |

### 3.3 关键数据流



1. **上行**：用户语音 → ASR → 规则引擎 → 大模型 NLU → 控制权交接管理器

2. **控制权判断**：

* 导航意图且当前控制方是主助手 → 发起进入 Agent 流程

* 当前控制方是 Agent → 转发给 Agent 处理

* 非导航意图且当前控制方是 Agent → 触发回退流程，交还控制权给主助手

1. **下行请求**：控制权交接管理器 → `capability_call` → 端云长连接 → 端侧 → 高德 Agent

2. **下行确认**：端侧 → `capability_ack` → 云侧

3. **上行结果**：端侧 Agent 异步执行完成 → `capability_result` → 云侧 → 恢复上下文 → TTS 播报

4. **控制权事件**：Agent 侧检测到非导航意图 / 导航流程结束 → `handover_event` → 云侧交还控制权

5. **状态事件**：端侧导航状态变更 → `navigation_event` → 云侧更新 `is_in_navigation` 缓存

## 4. 对话控制权交接机制（核心设计）

### 4.1 控制方定义

系统中存在两个对话控制方，任一时刻只有一个控制方持有对话控制权：



| 控制方      | 标识           | 持有控制权时的行为                                   |
| -------- | ------------ | ------------------------------------------- |
| 主语音助手    | `primary`    | 处理所有用户输入，包括导航意图和非导航意图；识别到导航意图后发起进入 Agent 流程 |
| 高德 Agent | `amap_agent` | 处理导航域用户输入；识别到非导航意图或导航流程结束后，主动交还控制权给主助手      |

### 4.2 进入 Agent 的触发条件

主语音助手识别到以下意图时，发起进入高德 Agent 流程：



| 触发意图        | 示例                | 进入方式                                  |
| ----------- | ----------------- | ------------------------------------- |
| 导航意图（有目的地）  | "导航到大新"、"带我去公司"   | 直接进入 Agent，携带 destination 参数          |
| 导航意图（无目的地）  | "开始导航"            | 直接进入 Agent，Agent 内部反问目的地              |
| 直接导航意图      | "导航到大新，直接走"       | 直接进入 Agent，携带 direct\_navigation=true |
| 导航控制意图（导航中） | "结束导航"、"重新导航到 xx" | 直接进入 Agent 控制接口，不经过对话交互               |
| 导航中查询意图     | "沿途有什么咖啡店"        | 直接进入 Agent 查询接口                       |

### 4.3 进入 Agent 的流程



```
用户："导航到大新"

\&#x20; │

\&#x20; ▼

主语音助手 NLU：识别为 navigation\\\_intent，destination=大新

\&#x20; │

\&#x20; ▼

控制权交接管理器：判断需要进入高德 Agent

\&#x20; │

\&#x20; ├─ 1. 保存当前上下文（对话历史、用户偏好等）

\&#x20; ├─ 2. 设置当前控制方 = amap\\\_agent

\&#x20; ├─ 3. 发送 capability\\\_call(capability=enter\\\_agent, params={destination, user\\\_input})

\&#x20; ├─ 4. 端侧 Agent 接收，初始化导航对话状态

\&#x20; ├─ 5. Agent 执行 POI 搜索等操作

\&#x20; └─ 6. Agent 通过 capability\\\_result 返回需要展示给用户的内容

\&#x20; │

\&#x20; ▼

云侧 TTS 播报 Agent 返回的内容（如"为你找到以下地址：1.大新地铁站 2.大新公园…"）

\&#x20; │

\&#x20; ▼

等待用户下一轮输入（当前控制方 = amap\\\_agent，后续输入转发给 Agent）
```

### 4.4 退出 Agent 的触发条件

以下情况触发退出高德 Agent，交还控制权给主语音助手：



| 触发条件           | 触发方     | 说明                                         |
| -------------- | ------- | ------------------------------------------ |
| 导航流程成功结束       | Agent 侧 | 用户到达目的地 / 导航完成，Agent 主动通知退出                |
| 用户主动取消导航       | Agent 侧 | 用户在 Agent 对话中说 "取消"、"算了"，Agent 完成取消后通知退出   |
| Agent 识别到非导航意图 | Agent 侧 | 用户说 "看下闹钟"、"今天天气" 等，Agent 判断超出能力范围，主动交还控制权 |
| 导航控制指令执行完成     | 主助手侧    | "结束导航" 等控制指令执行完成后，主助手直接收回控制权               |
| Agent 对话超时     | 云侧      | Agent 持有控制权超过一定时间（如 5 分钟）无用户输入，自动收回        |

### 4.5 退出 Agent 的流程



```
Agent 持有控制权期间，用户："帮我看下我的闹钟"

\&#x20; │

\&#x20; ▼

Agent 侧 NLU：识别为非导航意图（超出 Agent 能力范围）

\&#x20; │

\&#x20; ▼

Agent 主动发送 handover\\\_event(type=non\\\_navigation\\\_intent, current\\\_context)

\&#x20; │

\&#x20; ▼

云侧控制权交接管理器：

\&#x20; ├─ 1. 接收 handover\\\_event

\&#x20; ├─ 2. 恢复主助手上下文

\&#x20; ├─ 3. 设置当前控制方 = primary

\&#x20; ├─ 4. 保存 Agent 侧的导航上下文（POI 列表、目的地等）到 nav\\\_context

\&#x20; └─ 5. 将用户原始输入"帮我看下我的闹钟"交给主助手处理

\&#x20; │

\&#x20; ▼

主助手处理闹钟查询，TTS 播报："你明天有 3 个闹钟：7:00、8:30、9:00"

\&#x20; │

\&#x20; ▼

主助手检查 nav\\\_context：发现存在未完成的导航流程（WAITING\\\_POI\\\_SELECTION）

\&#x20; │

\&#x20; ▼

主助手主动召回："还需要继续导航到大新吗？（第一个地址是大新地铁站）"

\&#x20; │

\&#x20; ▼

用户："继续"

\&#x20; │

\&#x20; ▼

主助手识别为继续导航意图，重新进入 Agent（携带之前保存的 POI 列表和选择）
```

### 4.6 显式提示机制

为避免用户 "无感知地陷入 Agent"，进入和退出 Agent 时都有明确的语音提示：



| 时机             | 提示语示例                        | 说明                        |
| -------------- | ---------------------------- | ------------------------- |
| 进入 Agent 时     | "好的，正在为你导航"                  | 简洁提示，不强调 "已进入高德助手"，避免用户困惑 |
| Agent 回退到主助手时  | "好的，我来帮你查闹钟。另外，还需要继续导航到大新吗？" | 自然过渡，同时召回导航               |
| 导航结束退出 Agent 时 | "已到达目的地，导航结束"                | 明确告知导航状态                  |

> **设计原则**
> ：提示要自然，不要使用 "已进入高德导航助手"、"已退出高德导航助手" 这类技术化表述，用户不需要知道背后有两个 Agent。用户只需要感知到：导航相关的问题能得到正确回答，非导航问题也能得到正确回答。

## 5. 端云通信协议

### 5.1 通信通道

复用端侧（手机 App）与云侧之间的**现有长连接**，在其上扩展 "能力调用" 和 "控制权事件" 消息类型。不新建独立通道。

### 5.2 消息类型总览



| 消息类型                  | 方向  | 用途                               |
| --------------------- | --- | -------------------------------- |
| `capability_call`     | 云→端 | 发起能力调用（进入 Agent、Agent 对话、导航控制等）  |
| `capability_ack`      | 端→云 | 确认已接收 / 拒绝                       |
| `capability_result`   | 端→云 | 异步返回业务结果                         |
| `handover_event`      | 端→云 | Agent 侧发起的控制权交接事件（非导航意图回退、导航结束等） |
| `navigation_event`    | 端→云 | 导航状态变更事件推送                       |
| `capability_register` | 端→云 | 连接时上报支持的能力列表                     |

### 5.3 三阶段能力调用模型

所有端侧能力调用采用统一的三阶段消息交互：



| 阶段    | 方向  | 消息类型                | 作用                 | 延迟要求    |
| ----- | --- | ------------------- | ------------------ | ------- |
| 1. 请求 | 云→端 | `capability_call`   | 云侧发起能力调用           | —       |
| 2. 确认 | 端→云 | `capability_ack`    | 端侧立即确认 "已接收 / 已拒绝" | < 100ms |
| 3. 结果 | 端→云 | `capability_result` | 端侧异步执行完成后推送结果      | 取决于业务   |

### 5.4 capability\_call 消息格式



```
{

\&#x20; "msg\\\_id": "a1b2c3d4-5678-uuid",

\&#x20; "type": "capability\\\_call",

\&#x20; "capability": "agent\\\_dialog",

\&#x20; "params": {

\&#x20;   "user\\\_input": "第一个",

\&#x20;   "context": {

\&#x20;     "destination": "大新",

\&#x20;     "poi\\\_list": \\\[...]

\&#x20;   }

\&#x20; },

\&#x20; "timestamp": 1725000000000

}
```



| 字段           | 类型     | 必填 | 说明                    |
| ------------ | ------ | -- | --------------------- |
| `msg_id`     | string | 是  | 全局唯一 ID，关联请求、确认、结果    |
| `type`       | string | 是  | 固定为 `capability_call` |
| `capability` | string | 是  | 能力名称，见第 6 章接口定义       |
| `params`     | object | 是  | 能力参数                  |
| `timestamp`  | number | 是  | 请求发起时间戳               |

### 5.5 handover\_event 消息格式（控制权交接事件）



```
{

\&#x20; "msg\\\_id": "h1b2c3d4-5678-uuid",

\&#x20; "type": "handover\\\_event",

\&#x20; "event": "non\\\_navigation\\\_intent",

\&#x20; "data": {

\&#x20;   "user\\\_input": "帮我看下我的闹钟",

\&#x20;   "agent\\\_state": "WAITING\\\_POI\\\_SELECTION",

\&#x20;   "nav\\\_context": {

\&#x20;     "destination": "大新",

\&#x20;     "poi\\\_list": \\\[

\&#x20;       {"id": "poi\\\_001", "name": "大新地铁站", "address": "..."},

\&#x20;       {"id": "poi\\\_002", "name": "大新公园", "address": "..."}

\&#x20;     ]

\&#x20;   },

\&#x20;   "reason": "intent\\\_out\\\_of\\\_scope"

\&#x20; },

\&#x20; "timestamp": 1725000005000

}
```



| 字段                 | 类型     | 必填 | 说明                                                                                               |
| ------------------ | ------ | -- | ------------------------------------------------------------------------------------------------ |
| `event`            | string | 是  | 事件类型：`non_navigation_intent` / `navigation_completed` / `navigation_cancelled` / `agent_timeout` |
| `data.user_input`  | string | 是  | 触发回退的用户原始输入，交给主助手继续处理                                                                            |
| `data.agent_state` | string | 是  | Agent 侧当前对话状态，用于主助手恢复后召回                                                                         |
| `data.nav_context` | object | 否  | 导航上下文（目的地、POI 列表等），主助手保存用于后续召回                                                                   |
| `data.reason`      | string | 是  | 回退原因：`intent_out_of_scope` / `navigation_done` / `user_cancelled` / `timeout`                    |

### 5.6 统一错误码



| 错误码                        | 含义            | 用户提示建议           |
| -------------------------- | ------------- | ---------------- |
| `TIMEOUT`                  | 端侧执行超时        | "搜索有点慢，要不要再试一次？" |
| `NOT_FOUND`                | 未找到结果（POI 为空） | "找不到 xxx，无法为你导航" |
| `AGENT_ERROR`              | 高德 Agent 内部错误 | "导航出了点问题，请重试"    |
| `SDK_ERROR`                | 高德 SDK 内部错误   | "导航出了点问题，请重试"    |
| `PERMISSION_DENIED`        | 权限不足（未授权定位）   | "请先开启定位权限"       |
| `CAPABILITY_NOT_SUPPORTED` | 端侧不支持该能力      | "当前版本不支持此功能"     |
| `CANCELLED`                | 用户取消了操作       | "好的，已取消"         |

端侧（集成高德 Agent SDK 后）暴露以下能力接口给云侧调用：

| 参数                  | 类型      | 必填 | 说明                                         |
| ------------------- | ------- | -- | ------------------------------------------ |
| `user_input`        | string  | 是  | 用户原始输入，如 "导航到大新"                           |

## 7. 异步回调机制

### 7.1 问题背景

进入 Agent、Agent 对话、导航启动等操作是异步的，耗时不确定。云侧发起 `capability_call` 后不能阻塞等待，需要端侧完成后主动推送结果，云侧能将结果关联到原始请求和上下文。

### 7.2 in-flight calls（待完成调用表）

云侧维护 `in-flight calls` 表，按 `msg_id` 存储每个已发起但未收到结果的调用上下文。

**每条记录包含：**



| 字段                 | 说明                              |
| ------------------ | ------------------------------- |
| `msg_id`           | 调用的唯一消息 ID                      |
| `capability`       | 能力名称                            |
| `params`           | 调用参数                            |
| `controller`       | 发起调用时的控制方（primary /amap\_agent） |
| `agent_session_id` | 关联的 Agent 会话 ID（如果有）            |
| `nav_context`      | 发起调用时的导航上下文                     |
| `user_input`       | 发起调用时的用户原始输入                    |
| `start_time`       | 发起时间戳                           |
| `timeout_id`       | 超时定时器 ID                        |

### 7.3 处理流程



```
1\\. 云侧决定调用能力（如 enter\\\_agent）

\&#x20; │

\&#x20; ▼

2\\. 生成 msg\\\_id，记录到 in-flight calls

\&#x20; 保存：controller、agent\\\_session\\\_id、nav\\\_context、user\\\_input

\&#x20; │

\&#x20; ▼

3\\. 发送 capability\\\_call 到端侧

\&#x20; │

\&#x20; ▼

4\\. 设置超时定时器（enter\\\_agent 10 秒，agent\\\_dialog 8 秒，stop\\\_navigation 5 秒）

\&#x20; │

\&#x20; ├──────────────────────────────────┐

\&#x20; │                                  │

\&#x20; ▼                                  ▼

5\\. 收到 capability\\\_ack             6. 超时触发

\&#x20; status=accepted → 什么都不做       删除 in-flight 记录

\&#x20; status=rejected → 删除记录，       TTS 告知用户超时

\&#x20; 按 error 处理                      收回控制权（如果在 Agent 中）

\&#x20; │

\&#x20; ▼

7\\. 收到 capability\\\_result

\&#x20; 按 msg\\\_id 查找 in-flight call

\&#x20; │

\&#x20; ├─ 找到 → 删除记录，清除超时

\&#x20; │        用 result + 保存的上下文继续对话流程

\&#x20; │        （如果是 agent\\\_dialog 且 handover\\\_requested=true，触发控制权回退）

\&#x20; │

\&#x20; └─ 没找到 → 已超时或已处理，忽略（幂等）
```

### 7.4 超时策略



| 能力                | 超时时长 | 超时处理                               |
| ----------------- | ---- | ---------------------------------- |
| `enter_agent`     | 10 秒 | TTS"导航启动有点慢，要不要再试一次？"，收回控制权，回 IDLE |
| `agent_dialog`    | 8 秒  | TTS"响应有点慢，请再说一遍"，保持当前状态            |
| `exit_agent`      | 3 秒  | 忽略超时，直接清理本地会话记录                    |
| `stop_navigation` | 5 秒  | TTS"导航停止超时，请手动在手机上结束导航"            |
| `query_nvi_about` | 5 秒  | TTS"查询超时，请稍后再试"，保持 NAVIGATING      |

### 7.5 幂等与去重



* 端侧可能因网络重发重复推送 `capability_result`，云侧按 `msg_id` 去重；

* 云侧重复发送 `capability_call` 时使用相同 `msg_id`，端侧按 `msg_id` 去重；

* `handover_event` 可能重复推送，云侧按当前控制方状态去重（如果已经是 primary，忽略重复的回退事件）。

## 8. 状态机设计

### 8.1 双状态机职责分离

系统中存在两个独立的状态机，职责不同：



| 状态机             | 维护方          | 包含内容                                                                                                                           |
| --------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| **控制权状态机**      | 云侧           | 当前对话控制方：`PRIMARY` / `AMAP_AGENT`                                                                                               |
| **Agent 对话状态机** | 端侧（Agent 内部） | Agent 内部导航对话状态：`WAITING_DESTINATION` / `POI_SEARCHING` / `WAITING_POI_SELECTION` / `NAV_STARTING` / `NAVIGATING` / `COMPLETED` |
| **导航执行状态机**     | 端侧           | 是否在导航中：`NOT_NAVIGATING` / `NAVIGATING`                                                                                         |

> **关键原则**
> ：Agent 对话状态由高德 Agent 内部维护，云侧不直接管理，只通过
> `agent_state`
> 字段同步感知。云侧只管理控制权状态（谁在持有对话控制权）。

### 8.2 控制权状态机

#### 状态定义



| 状态           | 含义                            | 进入条件                          |
| ------------ | ----------------------------- | ----------------------------- |
| `PRIMARY`    | 主语音助手持有控制权，处理所有用户输入           | 初始状态 / Agent 回退 / 导航结束 / 用户取消 |
| `AMAP_AGENT` | 高德 Agent 持有控制权，导航域输入转发给 Agent | 主助手识别到导航意图，调用 enter\_agent 成功 |

#### 状态转移规则



| 当前状态         | 触发事件                              | 动作                                                            | 目标状态             |
| ------------ | --------------------------------- | ------------------------------------------------------------- | ---------------- |
| `PRIMARY`    | 识别到导航意图                           | 调用 `enter_agent`，保存上下文，TTS 播报 Agent 返回内容                      | `AMAP_AGENT`     |
| `PRIMARY`    | 非导航意图                             | 主助手直接处理                                                       | `PRIMARY`（保持）    |
| `AMAP_AGENT` | 用户输入（导航域）                         | 调用 `agent_dialog`，TTS 播报 Agent 返回内容                           | `AMAP_AGENT`（保持） |
| `AMAP_AGENT` | Agent 返回 handover\_requested=true | 触发控制权回退：恢复主助手上下文，将用户输入交给主助手处理，保存 nav\_context 用于召回，主助手处理完主动召回 | `PRIMARY`        |
| `AMAP_AGENT` | Agent 推送 navigation\_completed 事件 | 调用 `exit_agent`，清理会话，TTS"已到达目的地，导航结束"                         | `PRIMARY`        |
| `AMAP_AGENT` | 用户说 "结束导航"（导航中）                   | 调用 `stop_navigation`，成功后调用 `exit_agent`，TTS"好的，已结束导航"         | `PRIMARY`        |
| `AMAP_AGENT` | Agent 对话超时（无用户输入超过 5 分钟）          | 调用 `exit_agent(reason=timeout)`，清理会话，保存 nav\_context          | `PRIMARY`        |
| `AMAP_AGENT` | 用户说 "取消"（未开始导航）                   | 调用 `agent_dialog`，Agent 完成取消后返回，调用 `exit_agent`，TTS"好的，已取消"   | `PRIMARY`        |

### 8.3 Agent 对话状态（端侧维护，云侧感知）



| 状态                      | 含义                       | 云侧感知方式                                              |
| ----------------------- | ------------------------ | --------------------------------------------------- |
| `WAITING_DESTINATION`   | Agent 识别到导航意图但目的地缺失，正在反问 | `enter_agent` / `agent_dialog` 返回的 `agent_state` 字段 |
| `POI_SEARCHING`         | Agent 正在搜索 POI           | 同上                                                  |
| `WAITING_POI_SELECTION` | Agent 已返回 POI 列表，等待用户选择  | 同上                                                  |
| `NAV_STARTING`          | Agent 正在启动导航             | 同上                                                  |
| `NAVIGATING`            | 导航已成功启动，正在进行中            | 同上 + `navigation_started` 事件                        |
| `COMPLETED`             | 导航完成（到达目的地）              | `navigation_completed` 事件                           |

> 云侧不需要管理这些状态的转移逻辑，只需要在每次
> `agent_dialog`
> 返回时读取
> `agent_state`
> ，用于：
> 判断是否需要主动召回（如回退到主助手后，如果 agent_state 是 WAITING_POI_SELECTION，需要召回）；
> 公共参数中携带给大模型，帮助大模型理解当前导航进度。

### 8.4 导航执行状态（端侧维护，事件同步）

端侧维护导航执行状态，状态变更时通过 `navigation_event` 推送到云侧：



| 事件类型                  | 触发时机               | 推送内容                                    |
| --------------------- | ------------------ | --------------------------------------- |
| `navigation_started`  | 导航成功启动             | `{ route_id, destination, start_time }` |
| `navigation_ended`    | 导航结束（到达 / 取消 / 异常） | `{ reason, route_id }`                  |
| `navigation_rerouted` | 偏航重算               | `{ new_route_id, reason }`              |

云侧维护 `is_in_navigation` 缓存，值来自最近一次端侧推送的导航事件。

## 9. 意图路由与规则引擎

### 9.1 混合架构：规则引擎 + 大模型

采用**规则引擎前置 + 大模型兜底**的混合架构，关键意图由规则引擎快速判断，保证稳定性和低延迟；模糊语义由大模型补全。

### 9.2 意图分类



| 意图类别                    | 示例                       | 路由目标          | 处理方            |
| ----------------------- | ------------------------ | ------------- | -------------- |
| `navigation_intent`     | "导航到大新"、"开始导航"、"带我去公司"   | 进入高德 Agent    | 规则引擎优先         |
| `navigation_control`    | "结束导航"、"重新导航到 xx"、"取消导航" | 直接调用控制接口      | 规则引擎           |
| `navigation_query`      | "沿途有什么咖啡店"、"还有多远"        | 进入 Agent 查询接口 | 规则引擎 + 大模型     |
| `non_navigation_intent` | "看下我的闹钟"、"今天天气"、"讲个笑话"   | 主语音助手自身能力     | 规则引擎排除 + 大模型分类 |
| `cancel_intent`         | "取消"、"算了"、"不用了"          | 根据当前状态处理      | 规则引擎           |

### 9.3 控制权感知的意图路由

意图路由需要结合**当前控制方**状态，并采用**云侧前置判断 + Agent 兜底**的双层架构：



| 当前控制方        | 识别意图                              | 路由决策                                         |
| ------------ | --------------------------------- | -------------------------------------------- |
| `PRIMARY`    | navigation\_intent                | 进入 Agent（调用 enter\_agent）                    |
| `PRIMARY`    | navigation\_control（但不在导航中）       | 主助手回复 "当前不在导航中"，不进入 Agent                    |
| `PRIMARY`    | non\_navigation\_intent           | 主助手直接处理                                      |
| `AMAP_AGENT` | 高置信度非导航意图（闹钟/天气/讲笑话等）            | **云侧前置拦截，不转发给 Agent**，直接由主助手处理，保留 nav\_context，处理完主动召回 |
| `AMAP_AGENT` | 导航域意图 / 模糊意图                     | 转发给 Agent（agent\_dialog），由 Agent 处理          |
| `AMAP_AGENT` | Agent 返回 handover\_requested=true | 回退到主助手，主助手处理原始输入                             |

> **核心设计：云侧前置判断层（安全网）**
>
> 在 Agent 持有控制权期间，云侧**不直接无脑转发**用户输入给 Agent，而是先经过一层**轻量意图判断**：
>
> 1. **规则引擎快速判断**：用关键词匹配高置信度非导航意图（如"闹钟"、"天气"、"讲笑话"、"打电话"等），命中则**不转发给 Agent**，直接由主助手处理；
> 2. **大模型兜底判断**：规则引擎未命中时，调用大模型做一次轻量意图分类（导航域 vs 非导航域），如果大模型高置信度（>0.9）判断为非导航意图，同样不转发；
> 3. **模糊意图转发**：规则和大模型都无法明确判断（置信度 0.5-0.9），或判断为导航域意图时，才转发给 Agent 处理；
> 4. **Agent 回退兜底**：即使转发给 Agent，Agent 也可能识别到非导航意图并返回 `handover_requested=true`，云侧收到后同样回退到主助手。
>
> **为什么需要这层？** 高德 Agent SDK 的非导航意图回退能力是黑盒、不可控（见第 14 章风险 R1）。云侧前置判断层作为**安全网**，确保即使 Agent SDK 不支持非导航意图回退，场景 5（非导航意图）也能通过云侧拦截正确处理。这是 5 个边界场景全部可覆盖的关键保障。

### 9.4 规则引擎关键规则



| 规则 ID             | 匹配模式                                 | 意图                               | 置信度  | 状态条件                    |
| ----------------- | ------------------------------------ | -------------------------------- | ---- | ----------------------- |
| `nav_001`         | `导航到(.+)\|去(.+)\|带我去(.+)\|帮我导航到(.+)` | navigation\_intent               | 0.85 | controller=PRIMARY      |
| `nav_002`         | `开始导航\|导航吧`                          | navigation\_intent（无目的地）         | 0.9  | controller=PRIMARY      |
| `nav_home_001`    | `回家\|导航到家\|去家`                       | navigation\_intent（常用地址 home）    | 0.95 | controller=PRIMARY      |
| `nav_company_001` | `去公司\|导航到公司\|上班`                     | navigation\_intent（常用地址 company） | 0.95 | controller=PRIMARY      |
| `stop_nav_001`    | `结束导航\|停止导航\|别导航了`                   | navigation\_control（停止）          | 0.95 | is\_in\_navigation=true |
| `cancel_001`      | `取消\|算了\|不用了\|别弄了`                   | cancel\_intent                   | 0.95 | 任意                      |
| `nav_query_001`   | `沿途(.+)\|附近(.+)\|路上(.+)`             | navigation\_query                | 0.85 | is\_in\_navigation=true |

### 9.5 规则引擎与大模型分工



| 意图 / 判断        | 处理方            | 实现方式                     | 置信度      |
| -------------- | -------------- | ------------------------ | -------- |
| 取消意图           | 规则引擎           | 关键词匹配                    | 0.95     |
| 导航控制（结束 / 停止）  | 规则引擎           | 关键词匹配 + 状态条件             | 0.95     |
| 常用地址映射（家 / 公司） | 规则引擎           | 关键词直接映射                  | 0.95     |
| 导航意图识别         | 规则引擎优先 + 大模型兜底 | 规则匹配常见表达；未命中时大模型判断       | 0.85-0.9 |
| 目的地槽位提取        | 大模型            | 模糊地名、简称、别名需要语义理解         | —        |
| 非导航意图分类        | 规则引擎排除 + 大模型确认 | 规则引擎先排除导航关键词；未命中则大模型判断   | —        |
| Agent 侧非导航意图检测 | Agent 内部       | Agent 自己的 NLU 判断是否超出能力范围 | —        |

## 10. 公共参数设计

### 10.1 每次语音请求携带的公共参数



| 参数名                | 类型      | 说明                                         | 来源                                |
| ------------------ | ------- | ------------------------------------------ | --------------------------------- |
| `controller`       | string  | 当前对话控制方：`primary` / `amap_agent`           | 云侧控制权状态机                          |
| `is_in_navigation` | boolean | 是否正在导航中                                    | 端侧导航事件推送缓存                        |
| `agent_session_id` | string  | 当前 Agent 会话 ID（controller=amap\_agent 时有值） | 云侧会话管理                            |
| `agent_state`      | string  | Agent 当前对话状态（最近一次同步）                       | `enter_agent` / `agent_dialog` 返回 |
| `nav_context`      | object  | 导航上下文（目的地、POI 列表等）                         | Agent 返回 / 云侧保存                   |
| `nav_destination`  | string  | 当前导航目的地关键词                                 | nav\_context                      |

### 10.2 公共参数的作用



* **大模型 NLU**：根据 `controller` 和 `agent_state` 理解当前对话处于什么阶段，做出更准确的意图判断；

* **规则引擎**：根据 `controller`、`is_in_navigation`、`agent_state` 做状态条件判断（如 `stop_nav_001` 只在 is\_in\_navigation=true 时命中）；

* **控制权交接管理器**：根据 `controller` 决定当前用户输入是直接处理还是转发给 Agent；

* **主动召回**：回退到主助手后，根据 `agent_state` 和 `nav_context` 判断是否存在未完成的导航流程，决定是否主动召回。

## 11. 边界场景处理

### 11.1 场景 1：用户说 "开始导航"（未提供目的地）



| 项目       | 内容                                                                   |
| -------- | -------------------------------------------------------------------- |
| 用户输入     | "开始导航"                                                               |
| 当前控制方    | PRIMARY                                                              |
| 规则引擎输出   | 命中 `nav_002`：navigation\_intent，destination=null                     |
| 处理动作     | 调用 `enter_agent(user_input="开始导航")`，Agent 内部识别目的地缺失，反问用户             |
| Agent 返回 | `reply="请问要去哪里？"`, `agent_state="WAITING_DESTINATION"`               |
| 云侧 TTS   | "请问要去哪里？"                                                            |
| 状态转移     | controller: PRIMARY → AMAP\_AGENT；agent\_state: WAITING\_DESTINATION |
| 后续       | 用户说 "大新" → 云侧转发给 Agent（agent\_dialog）→ Agent 搜索 POI → 返回列表           |

> **设计要点**
> ：无目的地的导航意图也直接进入 Agent，由 Agent 内部处理反问和目的地补全。云侧不需要自己实现 WAITING_DESTINATION 状态的管理。
>
> **兜底方案**：若 Agent SDK 不支持无目的地时主动反问，云侧可前置处理：识别到 `destination=null` 时不进入 Agent，主助手直接反问"请问要去哪里？"，用户补充目的地后再进入 Agent。

### 11.2 场景 2：用户说 "导航到大新，直接导航，不要废话"



| 项目       | 内容                                                                         |
| -------- | -------------------------------------------------------------------------- |
| 用户输入     | "导航到大新，直接导航，不要废话"                                                          |
| 当前控制方    | PRIMARY                                                                    |
| 规则引擎输出   | 命中 `nav_001`，提取 destination = 大新；大模型识别 direct\_navigation=true             |
| 处理动作     | 调用 `enter_agent(user_input=..., destination="大新", direct_navigation=true)` |
| Agent 行为 | Agent 收到 direct\_navigation=true，内部完成 POI 搜索→取第一个→启动导航，跳过选择交互              |
| Agent 返回 | `reply="好的，已为你导航到大新地铁站"`, `agent_state="NAVIGATING"`                       |
| 状态转移     | controller: PRIMARY → AMAP\_AGENT；agent\_state: NAVIGATING                 |

> **设计要点**
> ：
> `direct_navigation`
> 参数通过
> `enter_agent`
> 的入参传递给 Agent，Agent 内部支持跳过 POI 选择。
>
> **兜底方案（推荐）**：如果 Agent SDK 不支持 `direct_navigation` 参数，云侧在 `enter_agent` 成功后**紧接着**发送 `agent_dialog(user_input="直接选第一个，不要问")`，由 Agent 对话层理解并执行。或云侧自己先调 `query_poi_list` 取第一个，再直接调 `start_navigation`。

### 11.3 场景 3：用户说 "导航到 xxx"（极端词，搜不到任何 POI）



| 项目       | 内容                                                                        |
| -------- | ------------------------------------------------------------------------- |
| 用户输入     | "导航到 asdfghjkl"                                                           |
| 当前控制方    | PRIMARY                                                                   |
| 处理动作     | 调用 `enter_agent(destination="asdfghjkl")`                                 |
| Agent 行为 | Agent 内部搜索 POI，返回空列表                                                      |
| Agent 返回 | `reply="找不到 asdfghjkl，无法为你导航"`, `agent_state="COMPLETED"`                 |
| 云侧处理     | TTS 播报 Agent 返回内容；检测到 agent\_state=COMPLETED 且导航未启动，调用 `exit_agent`，收回控制权 |
| 状态转移     | controller: AMAP\_AGENT → PRIMARY                                         |

> **设计要点**
> ：搜不到的情况由 Agent 内部处理，生成报错话术。云侧检测到 Agent 状态为 COMPLETED 且未启动导航时，主动退出 Agent 并收回控制权，避免 Agent 会话悬挂。
>
> **兜底方案（话术覆盖）**：Agent 对极端词的处理不可预测，可能返回模糊推荐或强行匹配不相关结果。云侧在 `enter_agent` 返回后检查 `nav_context.poi_list`：如果为空或 Agent 状态异常，云侧**覆盖 Agent 的回复**，统一用主助手话术播报"找不到 xxx，无法为你导航"，保证体验一致性。

### 11.4 场景 4：出现 POI 列表后，用户说 "开始导航"（没有说第 N 个）



| 项目       | 内容                                                                            |
| -------- | ----------------------------------------------------------------------------- |
| 前置状态     | controller=AMAP\_AGENT，agent\_state=WAITING\_POI\_SELECTION，POI 列表已展示         |
| 用户输入     | "开始导航"                                                                        |
| 处理动作     | 云侧转发给 Agent：`agent_dialog(user_input="开始导航")`                                 |
| Agent 行为 | Agent 内部状态依赖消歧：当前在 WAITING\_POI\_SELECTION 状态，"开始导航" 被理解为确认选择，默认取第一个 POI 启动导航 |
| Agent 返回 | `reply="好的，已为你导航到大新地铁站"`, `agent_state="NAVIGATING"`                          |
| 状态转移     | agent\_state: WAITING\_POI\_SELECTION → NAVIGATING                            |

> **设计要点**
> ：状态依赖消歧由 Agent 内部处理。Agent 知道当前在等待 POI 选择，能正确理解 "开始导航" 是 "确认选择第一个" 的意思。
>
> **兜底方案（推荐，云侧前置转换）**：如果 Agent SDK 不支持状态依赖消歧（可能把"开始导航"理解为新的无目的地导航意图，导致再次反问），云侧规则引擎前置处理：当 `controller=AMAP_AGENT` 且 `agent_state=WAITING_POI_SELECTION` 时，识别到"开始导航/走吧/出发"类指令，**自动转换为"第一个"**再转发给 Agent。这个方案不依赖 Agent 的状态消歧能力，100% 可控。

### 11.5 场景 5：出现 POI 列表后，用户说 "帮我看下我的闹钟"（非导航意图）



| 项目       | 内容                                                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 前置状态     | controller=AMAP\_AGENT，agent\_state=WAITING\_POI\_SELECTION，POI 列表已展示                                                                            |
| 用户输入     | "帮我看下我的闹钟"                                                                                                                                       |
| **主方案处理** | **云侧前置判断层拦截**：规则引擎匹配到"闹钟"关键词，高置信度判断为非导航意图 → **不转发给 Agent**，直接由主助手处理，同时保留 nav\_context                                                                      |
| 主助手处理    | 主助手调用闹钟能力，返回："你明天有 3 个闹钟：7:00、8:30、9:00"                                                                                                         |
| 主动召回     | 主助手检查 nav\_context，发现存在未完成的导航流程（agent\_state=WAITING\_POI\_SELECTION），主动提示："还需要继续导航到大新吗？（第一个地址是大新地铁站）"                                           |
| 用户后续     | "继续" → 主助手识别为继续导航意图 → 重新进入 Agent（携带之前保存的 POI 列表，直接发送 "第一个" 给 Agent）                                                                              |
| 状态转移     | controller 保持 PRIMARY（云侧前置拦截，不进入 Agent）→ 用户说 "继续" 后 → AMAP\_AGENT（重新进入）                                                                            |
| **兜底方案** | 若云侧前置判断未命中（模糊意图），则转发给 Agent；Agent 识别到超出导航域能力范围，返回 `handover_requested=true` → 云侧回退到主助手，后续流程同上                                                              |

> **设计要点（核心场景，主方案为云侧前置判断）**
> ：
> **主方案：云侧前置判断层拦截（推荐）**
> ：在转发给 Agent 之前，云侧规则引擎+大模型先做轻量意图判断，高置信度非导航意图直接不转发，由主助手处理。这个方案**不依赖 Agent SDK 的任何特殊能力**，100% 可控，是场景 5 可覆盖的关键保障。
> **上下文保留**
> ：云侧前置拦截时，保存当前 nav\_context（POI 列表、目的地等），不丢失；
> **主助手无缝接管**
> ：主助手直接处理用户原始输入，用户感知不到背后的控制权判断；
> **主动召回**
> ：主助手处理完非导航请求后，检查是否存在未完成的导航流程，主动提示用户是否继续，避免用户丢失导航进度；
> **重新进入恢复**
> ：用户说 "继续" 后，主助手重新进入 Agent，并携带之前保存的上下文，不需要用户重新说目的地；
> **兜底方案：Agent 侧主动回退**
> ：若云侧前置判断未命中（模糊意图），转发给 Agent 后，Agent 识别到非导航意图时主动请求交还控制权，作为兜底。

## 13. 实现建议

### 13.1 端侧实现

> **实现范围约束**
>
> ：所有导航相关能力（高德 Agent SDK、高德导航 SDK、ASR 语音识别）
>
> **仅在手机 App 端实现**
>
> 。眼镜端不集成任何高德 SDK，仅通过手机 App 端获取导航状态和 HUD 展示数据。



1. **集成高德 Agent SDK**：按照高德 Agent SDK 集成文档，在手机 App 中引入 SDK，初始化 Agent 配置（API Key、语音配置等）；

2. **集成高德 AIoT SDK ASR 服务**：在手机 App 端集成语音识别能力，调用高德 AIoT SDK 的 ASR 接口（`https://aiot.amap.com/rest/aiot/asr`）将用户语音转为文字，详见第 16 章；

3. **端云通信适配层**：实现 `capability_call` 接收、`capability_ack` 立即返回、`capability_result` 异步推送；实现 `handover_event` 和 `navigation_event` 的主动推送；

4. **Agent 能力封装**：将高德 Agent SDK 的能力封装为 5 个标准接口（`enter_agent`、`agent_dialog`、`exit_agent`、`stop_navigation`、`query_nvi_about`）；

5. **非导航意图检测**：确认高德 Agent SDK 是否支持 "识别到非导航意图时主动回退" 的能力；如果不支持，需要在端侧适配层增加一层 NLU 判断，识别到非导航意图时主动发送 `handover_event`；

6. **导航执行状态机**：维护 `NOT_NAVIGATING` / `NAVIGATING` 状态，状态变更时推送 `navigation_started` / `navigation_ended` / `navigation_rerouted` 事件；

7. **Agent 会话管理**：管理 Agent 会话的创建、销毁、超时清理；

8. **眼镜端 HUD 数据同步**：将导航状态、路线信息、转向提示等数据通过手机 - 眼镜通信通道同步到眼镜端展示；眼镜端不做任何导航计算，仅做展示；

9. **能力注册**：连接时上报支持的能力列表和 Agent SDK 版本信息。

### 13.2 云侧实现



1. **控制权交接管理器**：实现 `PRIMARY` / `AMAP_AGENT` 两个控制方状态的管理，包括进入 Agent、退出 Agent、非导航意图回退、上下文保存与恢复、主动召回等核心逻辑；

2. **规则引擎**：实现规则表加载、匹配、状态条件判断（controller、is\_in\_navigation、agent\_state）；初期实现 8-10 条核心规则；

3. **大模型 NLU**：在规则引擎未命中或低置信度时调用，输出意图 + 槽位；接收规则引擎 hints；

4. **能力调用编排层**：维护 in-flight calls 表，实现上下文保存与恢复、超时管理、幂等去重；

5. **端云通信客户端**：发送 `capability_call`，接收 `capability_ack` / `capability_result` / `handover_event` / `navigation_event`；

6. **handover\_event 处理**：接收 Agent 侧推送的控制权交接事件，触发回退流程，恢复主助手上下文，保存导航上下文，将用户输入交给主助手，处理完主动召回；

7. **导航事件处理**：接收端侧推送的导航事件，更新 `is_in_navigation` 缓存；

8. **公共参数填充**：每次请求时将 `controller`、`is_in_navigation`、`agent_session_id`、`agent_state`、`nav_context` 填充到公共参数；

9. **Agent 会话超时管理**：Agent 持有控制权超过 5 分钟无用户输入时，自动退出 Agent 并收回控制权。

| V1 | 无目的地时是否主动反问 | 调用 `enter_agent(user_input="开始导航")`，不传 destination | Agent 返回 `reply="请问要去哪里？"`，`agent_state=WAITING_DESTINATION` | 场景 1 | 云侧前置：识别到 destination=null 时不进入 Agent，主助手直接反问 |
| V2 | 是否支持 `direct_navigation` 参数跳过 POI 选择 | 调用 `enter_agent(destination="大新", direct_navigation=true)` | Agent 内部跳过选择，直接取第一个 POI 启动导航，返回 `agent_state=NAVIGATING` | 场景 2 | 云侧在 enter_agent 后紧接着发 `agent_dialog("直接选第一个")`；或云侧自己先搜 POI 取第一个再直接启动 |

| V5 | ⭐ **非导航意图回退能力（最关键）** | 先进入 Agent 到 `WAITING_POI_SELECTION` 状态，再调用 `agent_dialog(user_input="帮我看下我的闹钟")` | Agent 识别到超出能力范围，返回 `handover_requested=true`，`handover_reason="intent_out_of_scope"`，而不是强行回答或答非所问 | 场景 5 | **云侧前置判断层作为主方案**：规则引擎+大模型先判断，高置信度非导航意图直接不转发给 Agent，由主助手处理。Agent 回退仅作为兜底 |
| V6 | Agent 话术是否可配置 | 查阅 Agent SDK 文档或联系技术支持，确认是否支持自定义回复模板 | 支持配置关键节点话术（POI 列表播报、导航开始、找不到等） | 品牌一致性 | 关键节点由云侧主助手生成回复，覆盖 Agent 默认话术 |
| V7 | 是否支持外部传入 POI 列表恢复上下文 | 调用 `enter_agent` 时传入已有的 `nav_context={poi_list, destination}` | Agent 能基于传入的 POI 列表继续对话，不需要重新搜索 | 场景 5 恢复 | 云侧重新进入 Agent 时直接发送"第一个"等选择指令，由 Agent 内部重新搜索后自动匹配 |

> **POC 结论判定标准**
>
> ：
> - V1-V4 中任意一项不支持，都有云侧兜底方案，不阻塞方案落地；
> - **V5（非导航意图回退）即使不支持，也不阻塞方案落地**，因为云侧前置判断层已作为主方案覆盖场景 5；
> - V5 支持时，场景 5 有双重保障（云侧前置 + Agent 回退）；V5 不支持时，场景 5 仅靠云侧前置判断，同样可覆盖；
> - V6-V7 为体验优化项，不影响核心功能落地。

### 附录 A：术语表



| 术语                 | 说明                                                     |
| ------------------ | ------------------------------------------------------ |
| POI                | Point of Interest，兴趣点，即地图上的具体地址 / 地点                   |
| NLU                | Natural Language Understanding，自然语言理解，识别用户意图和槽位        |
| 槽位                 | 意图的参数，如导航意图的 destination 槽位                            |
| 端侧                 | 手机 App，运行高德 Agent SDK 和导航 SDK 的一侧                      |
| 云侧                 | 雷鸟语音助手的大模型服务，负责全局意图识别和控制权管理                            |
| 高德 Agent SDK       | 高德提供的导航域 Agent 开发包，内置导航对话能力，内部封装高德导航 SDK               |
| 高德导航 SDK           | 高德提供的导航原子能力开发包（POI 搜索、路线规划、导航执行等）                      |
| 控制方                | 当前持有对话控制权的一方：primary（主语音助手）或 amap\_agent（高德 Agent）     |
| 控制权交接              | 对话控制权在主助手和高德 Agent 之间转移的过程                             |
| handover\_event    | Agent 侧发起的控制权交接事件消息（非导航意图回退、导航结束等）                     |
| Agent 会话           | 一次进入 Agent 到退出 Agent 之间的完整对话周期，由 agent\_session\_id 标识 |
| in-flight calls    | 云侧维护的待完成调用表，按 msg\_id 存储已发起但未收到结果的调用上下文                |
| capability\_call   | 端云通信协议中的能力调用请求消息（云→端）                                  |
| capability\_ack    | 端云通信协议中的确认消息（端→云）                                      |
| capability\_result | 端云通信协议中的结果回调消息（端→云）                                    |
| navigation\_event  | 端侧导航状态变更事件推送消息                                         |
| 主动召回               | 主助手处理完非导航请求后，主动提示用户是否继续未完成的导航流程                        |

### 附录 B：消息类型速查



| 消息类型                  | 方向  | 用途              | 关键字段                                                                              |
| --------------------- | --- | --------------- | --------------------------------------------------------------------------------- |
| `capability_call`     | 云→端 | 发起能力调用          | `msg_id`, `capability`, `params`                                                  |
| `capability_ack`      | 端→云 | 确认已接收 / 拒绝      | `msg_id`, `status`, `error`                                                       |
| `capability_result`   | 端→云 | 异步返回业务结果        | `msg_id`, `result`, `error`                                                       |

## 16. 语音识别（ASR）设计

### 16.1 概述

本方案采用**高德 AIoT SDK 提供的 ASR 语音识别服务**，在手机 App 端完成用户语音到文字的转换。ASR 是整个导航语音交互链路的入口，将用户的语音指令转为文字后，再交由云侧语音助手进行意图识别和导航流程编排。

> **实现范围**
>
> ：ASR 服务
>
> **仅在手机 App 端调用**
>
> ，眼镜端不集成语音识别能力，仅负责音频采集和透传（或由手机端直接采集音频）。

### 16.2 服务接口信息



| 项目      | 内容                                                                                                                                       |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 服务名称    | 高德 AIoT SDK 语音识别服务（ASR）                                                                                                                  |
| 接口地址    | `https://aiot.amap.com/rest/aiot/asr`                                                                                                    |
| 接口类型    | HTTP POST（RESTful）                                                                                                                       |
| 底层服务    | 开平透传阿里云智能语音交互服务                                                                                                                          |
| 阿里云接口文档 | [https://help.aliyun.com/zh/isi/developer-reference/api-reference-1](https://help.aliyun.com/zh/isi/developer-reference/api-reference-1) |
| 认证方式    | URL 参数携带高德开放平台申请的 Key（`VI_KEY`）                                                                                                          |
| 最后更新    | 2026-08-19                                                                                                                               |

### 16.3 请求参数



| 参数名                                 | 类型      | 必填 | 说明                   | 取值范围                                                     |
| ----------------------------------- | ------- | -- | -------------------- | -------------------------------------------------------- |
| `key`                               | string  | 是  | 高德开放平台申请的智能硬件 Key    | —                                                        |
| `format`                            | string  | 是  | 音频格式                 | `PCM` / `WAV` / `OPUS` / `SPEEX` / `AMR` / `MP3` / `AAC` |
| `sample_rate`                       | int     | 是  | 音频采样率（Hz）            | `16000`（默认）/ `8000`                                      |
| `enable_punctuation_prediction`     | boolean | 否  | 是否启用标点预测             | `true` / `false`，建议 `true`                               |
| `enable_inverse_text_normalization` | boolean | 否  | 是否启用逆文本归一化（数字、日期等转写） | `true` / `false`，建议 `true`                               |
| `enable_voice_detection`            | boolean | 否  | 是否启用语音活动检测（VAD）      | `true` / `false`，建议 `true`                               |
| `disfluency`                        | boolean | 否  | 是否过滤语气词（"嗯"、"啊" 等）   | `true` / `false`，建议 `true`                               |

### 16.5 音频采集与格式建议



| 维度     | 建议配置                                        | 说明                   |
| ------ | ------------------------------------------- | -------------------- |
| 采样率    | 16000 Hz                                    | 语音识别标准采样率，识别效果最佳     |
| 位深     | 16 bit                                      | PCM 标准位深             |
| 声道     | 单声道（Mono）                                   | 语音识别只需单声道            |
| 传输格式   | `OPUS` 或 `AMR`                              | 压缩率高，减少传输延迟；手机端编码后上传 |
| 备选格式   | `PCM` / `WAV`                               | 无需编码，直接上传，但文件较大      |
| 音频时长   | 单次 ≤ 60 秒                                   | 导航指令通常较短，建议控制在 30 秒内 |
| VAD    | 启用 `enable_voice_detection=true`            | 自动检测语音起止点，过滤静音       |
| 标点     | 启用 `enable_punctuation_prediction=true`     | 识别结果带标点，便于后续 NLU 处理  |
| 逆文本归一化 | 启用 `enable_inverse_text_normalization=true` | 数字、日期、地址等正确转写        |
| 语气词过滤  | 启用 `disfluency=true`                        | 过滤 "嗯"、"啊"、"那个" 等语气词 |

### 16.6 ASR 在整体链路中的位置



```
┌─────────────────────────────────────────────────────────────────┐

│                        手机 App 端（端侧）                          │

│                                                                 │

│  ┌──────────┐    ┌──────────┐    ┌──────────────────────────┐  │

│  │ 音频采集   │───▶│ 高德 ASR  │───▶│ 识别文字（Final Text）    │  │

│  │ （麦克风）  │    │ 语音转文字  │    │                          │  │

│  └──────────┘    └──────────┘    └────────────┬─────────────┘  │

│                                                │                │

│                              （通过端云长连接上传文字 + 公共参数）  │

└────────────────────────────────────────────────┼────────────────┘

&#x20;                                                │

&#x20;                                                ▼

┌─────────────────────────────────────────────────────────────────┐

│                      雷鸟语音助手（云侧）                            │

│                                                                 │

│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │

│  │ 规则引擎   │───▶│ 大模型 NLU │───▶│ 控制权交接 │───▶│ 导航流程   │  │

│  │ 前置判断    │    │ 意图识别    │    │ 管理器     │    │ 编排       │  │

│  └──────────┘    └──────────┘    └──────────┘    └──────────┘  │

└─────────────────────────────────────────────────────────────────┘
```

**关键设计决策**：



1. **ASR 在端侧完成**：手机 App 端调用高德 ASR 接口将语音转为文字，再将文字上传到云侧。云侧不直接处理音频，减少端云传输带宽和延迟。

2. **文字上传而非音频上传**：ASR 完成后只上传识别文字（几十到几百字节），而非原始音频（几十 KB 到几 MB），显著降低端云通信开销。

3. **公共参数随文字一起上传**：每次上传识别文字时，携带当前导航状态（`controller`、`is_in_navigation`、`agent_state`、`nav_context` 等），帮助云侧正确理解上下文。

4. **眼镜端不做 ASR**：眼镜端仅负责音频采集（如有麦克风）和透传到手机端，或由手机端直接采集音频。眼镜端不集成语音识别能力。

### 16.7 错误处理



| 错误场景      | 可能原因              | 处理方式                                        |
| --------- | ----------------- | ------------------------------------------- |
| HTTP 请求失败 | 网络不可用、DNS 解析失败    | TTS"网络不太好，请检查网络连接后再试"；缓存音频，网络恢复后重试          |
| 接口返回错误码   | Key 无效、配额超限、格式不支持 | 记录错误日志；TTS"语音识别出了点问题，请再说一遍"；重新采集            |
| 识别结果为空    | 音频太短、静音、音量太低      | TTS"没听清，请再说一遍"；重新采集                         |
| 识别结果置信度低  | 环境噪音大、口音重         | 可选择将低置信度结果上传云侧，由大模型结合上下文判断；或 TTS 提示用户重复     |
| 音频格式不支持   | 采集格式不在支持列表内       | 端侧统一转码为 PCM/OPUS 后再上传                       |
| 超时        | 网络慢、音频文件大         | 设置 10 秒超时；超时后 TTS"识别有点慢，请再说一遍"；考虑使用更压缩的音频格式 |

### 16.8 与雷鸟现有 ASR 方案的关系



| 维度   | 高德 AIoT SDK ASR（本方案）                            | 雷鸟现有 ASR        |
| ---- | ----------------------------------------------- | --------------- |
| 部署位置 | 手机 App 端调用云端 REST 接口                            | 云侧服务            |
| 适用场景 | 导航域语音指令识别                                       | 全局语音助手          |
| 优势   | 高德优化过导航域识别（地名、地址等）；与高德 Agent SDK 同生态            | 全局统一，与主语音助手深度集成 |
| 建议   | **导航场景优先使用高德 ASR**，地名地址识别更准确；非导航场景可继续使用雷鸟现有 ASR | 作为全局兜底          |

> **待确认**
>
> ：高德 AIoT SDK ASR 是否对导航域词汇（地名、地址、POI 名称）有专门优化？建议在 POC 阶段对比高德 ASR 与雷鸟现有 ASR 在导航指令上的识别准确率，再决定最终选型。
