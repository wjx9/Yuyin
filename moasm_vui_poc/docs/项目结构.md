# 项目结构说明

本文是当前代码布局的唯一结构说明。目录按“运行入口 → 编排 → 工具 → 外部能力 → 客户端”划分，
不要把第三方请求代码直接放进 LangGraph 节点。

## 顶层目录

```text
moasm_vui_poc/
├── server_py/                 Python 后端
│   ├── chat_app.py            本地命令行入口
│   ├── serve.py               手机/客户端访问的 HTTP 入口（8000）
│   ├── orchestration/         LangGraph：分析、决策、执行批次、总结
│   ├── tools/                 统一工具层（ToolSpec/Registry/Runtime/Adapter）
│   ├── routing/               旧路由兼容层和 Handler 实现
│   ├── server/                HTTP 请求、会话、鉴权、ChatService
│   ├── mcp_skill/             MCP manifest、连接、动态技能适配
│   ├── store_client/          主服务访问技能商店的客户端
│   └── *_client/               第三方 provider 的 API/协议实现
├── skill_store/               技能商店服务（内部端口 9000，对外由 8000 代理）
│   ├── connectors/            官方 MCP 技能 manifest
│   ├── main.py                FastAPI 接口
│   ├── db.py/models.py        SQLite 数据库层
│   └── static/                管理员网页
├── client_flutter/            Android/iOS 手机端
│   └── lib/src/
│       ├── data/              HTTP API 与数据模型
│       ├── services/          GPS、日历、提醒、语音、TTS
│       ├── state/              Provider 状态控制器
│       └── ui/                 页面和通用组件
├── client_py/                 Python HTTP 客户端
├── ui_py/                     Python 终端呈现层
├── docs/                      设计、调研、结构说明
└── tests（分散在各包内）       与实现放在一起，便于局部回归
```

## 后端调用边界

```text
LangGraph
  → ToolRuntime
  → ToolRegistry
  → Adapter
  → 原有 Handler / HTTP provider / MCP client / 本地动作
```

新增能力时，优先新增 `ToolSpec` 和 Adapter；provider 只负责第三方协议，
`orchestration/` 不允许直接导入高德、Exa 或 MCP SDK。

## 命名规则

| 内容 | 规则 | 示例 |
|---|---|---|
| Python 包 | 小写下划线 | `mcp_skill`、`store_client` |
| 第三方包 | `<provider>_client` | `amap_client`、`exa_client` |
| LangGraph 文件 | 面向职责命名 | `graph.py`、`planner.py`、`composer.py` |
| 工具层文件 | `models`、`registry`、`runtime`、`adapters` | `tools/runtime.py` |
| Flutter 文件 | 小写下划线 | `chat_controller.dart` |
| 意图 ID | 小写下划线 | `amap_weather_live` |
| MCP 技能 ID | 稳定、全局唯一 | `weather-mcp` |

## 哪些文件不应再新增

- 不要在 `server_py` 根目录新增随意的业务脚本；入口只能是 `chat_app.py`、`serve.py`。
- 不要在 `orchestration/` 内直接写第三方 API 请求。
- 不要把新的 MCP 客户端散落到各个 provider；统一放在 `mcp_skill/`。
- 不要提交 `.env`、`*.pem`、`store.db`、`build/` 和 `.dart_tool/`。
