## 1. 项目定位与最新模型

**项目一句话**：把"出行 / 快递 / 地图 / 新闻 / 闲聊 / 股票 / 天气 / 点餐…"多个第三方能力，用
一层 **Gemini 意图分流** 编排成**单一语音对话入口**；再拆成 **PC 服务端（大脑）+ 客户端**
的 client-server 架构。本仓库是 PoC（`moasm_vui` = 把第三方能力接入下一代语音助手的可行性验证）。

**最新模型（官方 MCP 目录模式，2026-08-28 定）**：

| 角色 | 职责 | 不做什么 |
|---|---|---|
| **开发** | 把新 MCP 写成 `skill_store/connectors/*.json` 目录文件（评审后入库） | 不管运行期上架/下架 |
| **管理员** | 管理后台把目录技能**上架/下架**；自定义 MCP 的新增/删除（逃生通道） | **不再从零组装 MCP** |
| **用户** | 手机端选购 → 启用 → **自动弹凭证表单**填 API Key → 语音用起来 | 不接触 manifest |

数据流：`connectors/*.json`（官方 MCP 目录）+ 内置 Handler（`builtin_catalog.py` 轻量快照 / 主服务实际注册同步）→（商店启动自动同步 / 管理后台「重新同步目录」`POST /skills/sync-all`）→ `skills` 表（`publisher='catalog'` 官方目录 / `publisher='builtin'` 内置能力 / 其他=自定义）→ 管理后台统一目录表（上架/下架）→ 用户手机端启用即弹凭证 → server 按用户装配 → ≤30s 热插拔生效。

## 3. 核心数据流

### 3.1 用户说一句话 → MCP 技能返回

```
手机说话「深圳明天天气」
  → POST /chat {query, user_id:U, session_id, platform:mobile}
  → ChatService._assistant_for(U)     # store sync 版本命中 → 复用缓存图
  → AssistantGraph.run()
       analyze → decide → execute_batch
            → Dispatcher.execute(intent="weather_mcp")
            → MCPHandler.handle(query, ctx)          # ctx.slots={city:"深圳", days:1}
            → McpToolClient.call_tool("get_weather", args, timeout=30)
            → MCP Server 返回 → RouteResult(text, status=success)
       compose → Gemini 组织最终答复
  → POST /chat 200 {"text":"深圳明天…","intent":"weather_mcp",…}
```

### 3.2 热插拔生效时序（≤30s）

```
用户在手机端启用/停用/配凭证
  → 商店 version+1（同事务）
  → serve 侧 SkillRegistry 缓存 TTL 30s 到期后重新 GET /me/skills/sync
  → 版本变化 → ChatService 只重建该用户 graph（_cleanup_graph 关旧连接）
  → 下一次请求即走新路由
```

### 3.3 关键架构事实（决定热插拔可行）

| 事实 | 位置 | 意义 |
|---|---|---|
| 分类器每次调用都收意图列表 | `routing/classifier.py` | 无状态，换意图 = 换列表 |
| 意图列表来自 Dispatcher | `routing/dispatcher.py` | **热插拔改点是 dispatcher 的 handler 集合** |
| 注入点已存在 | `routing/factory.py` `build_dispatcher(extra_handlers=…, exclude_intents=…)` | MCP/内置技能做成 Handler 塞进去；`exclude_intents` 用于 replaces 顶替内置（买了技能后内置让位） |
| Handler 契约 | `routing/handler.py` | `intent/description/slots/pc_only` + `handle(query,context)` |
| 槽位类型仅 string/integer | `handler.py` / `classifier._clean_slots` | MCP JSON Schema 收敛映射到这两种 |
| 计划器白名单（已修复） | `orchestration/factory.py` | `allowed_intents = set(dispatcher.intents) \| _PLANNABLE_INTENTS` |

## 4. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 意图分流 | **Gemini functionCall**（`GeminiClassifier` + `GeminiActionDecider`） | 分类器无状态；每次调用传当前用户可用意图列表 |
| 编排 | **LangGraph**（`AssistantGraph`：analyze→decide→execute_batch→compose） | 内置能力与 MCP 技能同一张图 |
| 服务端 | Python `ThreadingHTTPServer`（同步）+ `server_py` 包 | 与历史兼容；MCP 异步经桥接 |

| 商店后端 | **FastAPI + uvicorn + SQLite** | `skill_store/`，21 接口 |
| 凭证存储 | **AES-GCM**（`STORE_MASTER_KEY` 来自 env） | 见 §7 |
| 手机端 | **Flutter**（原生，无 webview） | `client_flutter/`，VUI 语音 + 技能商店页 |
| 依赖安装 | 阿里云 PyPI 镜像 | `pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/` |

## 5. 技能商店后端

### 5.1 技能目录（connector catalog + builtin catalog）

商店目录统一管理三种技能来源，用户看到的是同一组可调用技能：

| 来源 | publisher | 接入方式 | 谁维护 |
|---|---|---|---|
| 官方 MCP 目录 | `catalog` | `connectors/*.json` 声明式，启动幂等同步 | 开发写 JSON，管理员只上架/下架 |
| 内置能力 | `builtin` | 商店端 `builtin_catalog.py` 轻量快照 + 主服务 `mcp_skill/builtin.py` 实际注册同步 | 代码自动同步 |
| 自定义 MCP | `poc`等 | 管理后台 probe 发现 → 手拼 manifest 发布（逃生通道） | 管理员 |

#### 5.1.1 官方 MCP 目录（connector catalog）—— 最新核心

`skill_store/connectors/*.json` 声明式目录，每个文件 = 一份完整 manifest + 可选 `default_status`：

- **同步**：商店启动 `lifespan` 自动跑 `catalog.sync_catalog()`；管理员也可点管理页
  「重新同步目录」→ `POST /skills/sync-all`（同时同步 connector 目录与内置能力；
  `POST /skills/catalog/sync` 仅同步 connector，兼容旧客户端）。
- **幂等语义**（`skill_store/catalog.py`）：
  - 新 connector 落库取 `default_status`（缺省 `inactive` = 待上架，不会悄悄上线）；
  - **已有行的 status 不被触碰**（保留管理员当前上架/下架）；
  - 仅 manifest 或 publisher 变化才写库；仅 manifest 变化才 bump 持有者（server ≤30s 重建图）。
- `publisher='catalog'` 标记目录技能，管理后台按此决定是否显示删除按钮（catalog/builtin 不可删除）。

#### 5.1.2 内置能力目录（builtin catalog）

内置能力（闲聊/闹钟/高德全家桶/新闻/出行/快递/音乐等 22 个 intent）也进入同一商店目录，保证直接访问商店（:9000）和通过主服务代理（:8000/skill-store）看到的内置能力一致。两条同步路径互补：

1. **商店端轻量快照**（`skill_store/builtin_catalog.py`）：商店启动 `lifespan` 自动跑，不依赖 Dispatcher/Gemini，按 env key 是否配置决定 active/inactive（缺 key 的能力标 inactive，不虚假展示）。`mcp_server.transport='local'`，执行时由 `LocalHandlerClient` 转回原 Handler。
2. **主服务实际注册同步**（`server_py/mcp_skill/builtin.py` + `POST /internal/builtin-skills/sync`）：主服务启动时把当前 Dispatcher 实际注册的内置能力（含 slots/keywords）同步到商店，覆盖商店端轻量快照的简化版本，确保目录展示与实际可执行能力一致。`ChatService.__init__` 中调用，失败不阻塞（`StoreUnavailable` 时降级，后续聊天请求中重试）。

内置能力 `always_enabled=True`，用户端默认启用；用户可在手机端停用（落一条 `enabled=0` 的偏好行），停用后不进 `/me/skills/sync` 的返回列表，server 侧重建图时排除。

### 5.2 数据模型（4 张表）

```sql
CREATE TABLE skills (
  skill_id   TEXT PRIMARY KEY, name TEXT, description TEXT, icon TEXT, intent TEXT,
  manifest   TEXT,      -- 完整 manifest JSON（含 mcp_server/tools/credentials）
  publisher  TEXT,      -- 'catalog'=官方目录 | 'builtin'=内置能力 | 其他=自定义
  status     TEXT DEFAULT 'active',   -- active 上架 | inactive 下架
  updated_at TEXT
);
CREATE TABLE user_skills (
  user_id TEXT, skill_id TEXT, enabled_at TEXT,
  PRIMARY KEY (user_id, skill_id)
  -- enabled 列由迁移 _migrate_user_skills_enabled() 补上（1=已启用，0=已选购但停用），
  -- 旧库缺列时 ALTER ADD，既有行默认 enabled=1（选购即启用，行为不变）
);
CREATE TABLE user_skill_versions (
  user_id TEXT PRIMARY KEY, version INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE user_skill_credentials (
  user_id TEXT, skill_id TEXT, cred_json TEXT,   -- AES-256-GCM 加密后的凭证 JSON
  updated_at TEXT,
  PRIMARY KEY (user_id, skill_id)
);
```

> 注意：`user_skill_credentials` 的密文列名是 `cred_json`（非 `encrypted`）；`enabled` 列不在建表 SCHEMA 中，而是通过 `db.py` 的迁移函数幂等添加。

### 5.3 版本号机制

- 独立表 `user_skill_versions(user_id PK, version)`，**每次写操作同一事务 +1**，
  不用 `MAX(updated_at)`（并发/同秒会撞值）。
- 技能发布/更新/下架/删除、目录 manifest 变化 → **bump 该技能所有持有者**版本。
- server 侧 `sync` 比对版本 → 只重建受影响用户的图。

### 5.4 intent 唯一性 + 内置冲突

- `POST /skills` 上架校验：**撞内置能力**（`_BUILTIN_INTENTS`，22 个，见 `main.py`）→ 409；
- 撞其他 active 技能同 intent → 409；
- server 装配时再过滤一次（双保险）。

## 6. 服务端接入与热插拔

### 6.1 MCP 适配层（`server_py/mcp_skill/`）

| 模块 | 职责 |
|---|---|
| `manifest.py` | `SkillManifest` 模型 + manifest→IntentSpec 映射（string/integer 收敛） |
| `client.py` | `McpToolClient`：每 MCP server 一个**常驻事件循环线程**，`run_coroutine_threadsafe` 同步等待，断线自动重连（方案 A）；`LocalHandlerClient`：内置能力 local transport 客户端，直接调原 Handler 不走网络 |
| `handler.py` | `MCPHandler(Handler)`：技能入口，`handle()` 调 entry_tool，失败收敛为干净 `RouteResult` |
| `registry.py` | `SkillRegistry`：按 user_id 拉取选购 + 版本缓存（TTL 30s），网络 IO 在锁外 |
| `provider.py` | `SkillCredentialProvider`：按 (user_id, skill_id) 取动态凭证明文（连接建立时才调用，**无缓存**，消除改 key 仍取旧值的边缘） |
| `builtin.py` | `build_builtin_manifests(dispatcher)`：把当前实际注册的内置 Handler 转成商店可展示的 manifest（`kind=builtin`，`transport=local`），主服务启动时同步到商店 |
| `assembly.py` | `build_mcp_handlers()`：P1 无商店模式下读本地 manifest JSON 装配 MCPHandler（兼容入口） |
| `mock_server.py` | 演示用 mock MCP（:9100，天气/股票/区域，可 `--require-auth` 模拟全请求鉴权） |

### 6.2 ChatService 按用户装配（`server/service.py`）

```python
def _assistant_for(self, user_id):
    # 未配置商店 → 恒为 base 图（纯内置或本地 manifest）
    if self._registry is None:
        return self._base_graph
    # 商店不可达 → 退回纯内置 base 图，不阻塞聊天
    try:
        version, skills = self._registry.resolve(user_id)  # 锁外：TTL 缓存多数命中
    except StoreUnavailable:
        return self._base_graph

    with self._lock:  # 锁内重验版本 → 杜绝并发重复构建
        hit = self._graphs.get(user_id)
        if hit and hit[0] >= version:   # ≥ 封掉"旧覆盖新"并发瞬态（版本回退保护）
            self._graphs.move_to_end(user_id)
            return hit[1]

        # 区分内置（local transport）与远程 MCP（http transport）
        builtin_skills = [m for m in skills if m.kind == "builtin"]
        mcp_skills = [m for m in skills if m.kind != "builtin"]
        # 双保险②：撞内置 intent 的 MCP 技能静默跳过（商店上架时已 409，这里兜底）
        mcp_skills = [m for m in mcp_skills if m.intent not in self._builtin_intents]

        # 内置能力：LocalHandlerClient 直接调原 Handler，不走网络
        local_handlers = [
            MCPHandler(m, LocalHandlerClient(self._base_graph._dispatcher.handler_for(m.intent)))
            for m in builtin_skills
        ]
        # 远程 MCP：McpToolClient 注入 SkillCredentialProvider（连接建立时取凭证明文）
        remote_clients = [
            McpToolClient(m, credential_provider=self._cred_provider, user_id=user_id)
            for m in mcp_skills
        ]
        # replaces 顶替内置：用户买了技能后，对应内置 intent 从 dispatcher 与白名单剔除
        exclude = {i for m in skills for i in m.replaces} | (self._builtin_intents - {"chitchat"})
        dispatcher = build_dispatcher(
            extra_handlers=local_handlers + [MCPHandler(m, c) for m, c in zip(mcp_skills, remote_clients)],
            exclude_intents=exclude,
        )
        graph = build_assistant_graph(dispatcher=dispatcher, exclude_intents=exclude)

        old = self._graphs.pop(user_id, None)
        if old:
            for c in old[2]:
                c.close()  # 换图回收旧常驻连接，防线程泄漏
        self._graphs[user_id] = (version, graph, local_clients + remote_clients)
        # LRU：MAX_GRAPHS=200，超出淘汰最久未用用户的图并关闭其连接
        while len(self._graphs) > MAX_GRAPHS:
            _, (_, _, cs) = self._graphs.popitem(last=False)
            for c in cs:
                c.close()
        return graph
```

要点：
- **版本回退保护**：复用条件 `hit[0] >= version` 而非 `==`；
- **双模式**：未配置商店 → 单图（P1 兼容）；配置商店 → base 图（纯内置，/health 无参语义）+ 按用户装配图；
- **内置与远程统一**：都走 `MCPHandler`，内置用 `LocalHandlerClient`（local transport），远程用 `McpToolClient`（http transport + 凭证注入）；
- **冲突过滤**：撞内置 intent 的 MCP 技能静默跳过（商店上架 409 是第一道，这里是第二道）；
- **replaces 顶替**：用户启用声明了 `replaces` 的技能后，对应内置 intent 从 dispatcher 和计划器白名单剔除（保留 `chitchat` 作为无工具时的安全兜底）；
- **LRU 上限**：`MAX_GRAPHS=200`，超出淘汰最久未用用户的图并关闭连接；
- **内置能力延迟同步**：主服务启动时尝试 `sync_builtin_skills`，失败不阻塞，后续聊天请求中重试（`_builtin_sync_done` 标志）。

### 6.3 路由确定性修复（P3 心脏）

1. **关键词确定性收窄**：manifest 加 `keywords`，命中即**确定性路由**到该技能，不被内置抢走。
2. **顶替内置**：manifest 加 `replaces`（如 `["amap_weather_live"]`），用户启用后内置让位。
3. **计划器白名单修复**：`_PLANNABLE_INTENTS` 静态常量当全集会挡掉 MCP 意图 →
   改为 `allowed_intents = set(dispatcher.intents) | _PLANNABLE_INTENTS`（与 dispatcher 同源）。

### 6.4 降级机制

- 商店宕机 → `StoreUnavailable` → **退回内置技能**，不 500 不崩；
- MCP server 不可达 → 该技能返回「暂不可用」，其他技能与闲聊不受影响；
- Gemini 不可用 → `KeywordClassifier._RULES` 兜底分类（无关键词规则的 MCP 技能落 chitchat）。

## 7. 动态凭证系统

### 7.1 连接模式全分类

| 维度 | 分类 |
|---|---|
| 凭证形态 | `none` 直接连接 · 单字段（Token）· 双字段（API Key+Secret）· 多字段（含非敏感配置）· OAuth · 文件凭证 |
| 传输 | HTTP(streamable) · SSE · stdio（P1 backlog） |
| 持有方 | `byok` 用户自带（POC 已做）· `platform` 发布方代管（商用）· OAuth（商用） |

### 7.2 credentials.schema 统一抽象

```json
"credentials": { "type": "none" | "byok", "schema": [
  {
    "key": "em_api_key", "label": "东方财富 API Key", "type": "secret",
    "required": true, "help": "获取方式", "placeholder": "输入 Key",
    "inject": { "where": "header" | "query", "name": "注入名", "prefix": "可选，如 Bearer " }
  }
]}
```

- `type`：`secret`（密码框）/ `string` / `number` / `select`（下拉，`options`）/ `boolean` /
  `textarea`、`file`（手机端按 secret 处理）。
- `inject`：`{"where":"header","name":"Authorization","prefix":"Bearer "}` →
  请求头加 `Authorization: Bearer <值>`；非 Bearer 直接 `{"where":"header","name":"em_api_key"}`；
  query 注入拼进 URL。
- 一个技能可声明多个字段，表单按 schema **动态渲染**，无需为新 MCP 改手机端代码。

### 7.3 存储与安全

- 凭证 **AES-256-GCM 加密**落库，`STORE_MASTER_KEY`（32 字节 hex，来自 env）只在商店进程内存，写凭证缺主密钥 **fail-closed** 500；
- **AAD 绑定** `user_id:skill_id`（`db.py::_aad`）：密文与属主绑定，防跨用户/跨技能互换密文，AAD 不匹配/被篡改/密钥不符 → 抛清晰错误（不裸抛 InvalidTag）；
- 手机端 `GET /me/credentials` 只回**脱敏**状态（secret/textarea/file 字段值置 null，其余非敏感字段返回明文供表单预填）；
- 明文仅 `GET /me/credentials/plain`（server_py 内部专用）在请求该用户的线程里短暂持有后注入 MCP 连接；
- **敏感字段留空=保留旧值**：脱敏 GET 不回传明文，用户只改非敏感字段保存时不能清掉已存密钥（`main.py::put_credentials` 合并逻辑）；
- 日志/异常脱敏，stdout 不打印 key。

### 7.4 用户端体验

- 启用 unconfigured byok 技能 → **立即自动弹凭证表单**（填 Key 即用）；
- 已配置 secret 不预填明文（留空=保留旧值）；select 等非敏感字段预填脱敏值；
- 未配凭证就说话 → 友好提示「需要先配置 API Key」。

## 8. 如何插入一个新技能（核心操作）

### 8.1 官方目录三步走（推荐）

**① 写 JSON** → `skill_store/connectors/<你的>.json`（字段见附录 A）

**② 同步进库** → 二选一：
- 管理后台点「**重新同步目录**」（推荐，免重启）；或
- 重启商店（启动时自动同步）。

**③ 上架** → 管理后台「官方 MCP 目录」找到该行 → 点「上架」。用户端立即可见、可启用。

完整模板：

```json
{
  "skill_id": "xxx-mcp",
  "name": "技能显示名",
  "icon": "📊",
  "description": "给语音助手看的描述：什么场景用、能答什么",
  "intent": "xxx_mcp",
  "pc_only": false,
  "entry_tool": "入口工具名",
  "query_slot": "query",
  "keywords": ["关键词1", "关键词2"],
  "replaces": [],
  "mcp_server": { "transport": "http", "url": "https://你的-mcp-地址" },
  "credentials": { "type": "none", "schema": [] },
  "tools": [
    {
      "name": "入口工具名",
      "description": "工具说明（LLM 用）",
      "input_schema": { "type": "object", "properties": { "query": { "type": "string" } }, "required": ["query"] }
    }
  ],
  "default_status": "inactive"
}
```

### 8.2 关键规则

| 规则 | 说明 |
|---|---|
| `intent` 唯一 | 不能撞内置能力（22 个）或其他 active 技能，撞了上架 409 |
| `transport` 是装饰 | 运行时只读 `mcp_server.url`，声明 `http` 即可 |
| `default_status` | `active`（同步即上架）/ `inactive`（待上架，缺省） |
| 凭证 schema | 用户填的字段都在 `credentials.schema` 声明，见 §7.2 |
| 改完生效 | 必须同步 + （若已选购用户）manifest 真变了才 bump，≤30s 生效 |

### 8.3 现成范例（拷一个改最省事）

| 范例 | 凭证形态 | 要点 |
|---|---|---|
| `weather.json` | `none` | 无鉴权，mock :9100 |
| `stock.json` | `none` | 无鉴权，mock :9100 |
| `region.json` | byok 双字段 | `api_key`(secret→`Authorization: Bearer`) + `region`(select→query) |
| `mcdonalds.json` | byok 单字段 | `mcp_token`(secret→`Authorization: Bearer`)，远程 mcp.mcd.cn |
| `eastmoney.json` | byok 单字段 | `em_api_key`(secret→header `em_api_key`，**非 Bearer**)，远程 mxapi.eastmoney.com |

### 8.4 自定义 MCP（逃生通道）

目录模式不够用时，管理后台「高级：添加自定义 MCP」：
1. 填 MCP server 地址 →「发现工具」（临时 Token / 高级请求头 JSON 支持非 Bearer 鉴权）；
2. 自动带出 manifest 表单，改 intent/关键词/credentials JSON → 发布；
3. 发布后出现在统一技能目录表中（publisher 非 catalog/builtin），可上架/下架/删除。

## 9. 三端交互（开发 / 管理员 / 用户）

### 9.1 手机端（用户）
